# 8 NPU 带宽简图

8 NPU、1 SSU（40 GiB/s）、每卡 6 个约 200K 长请求和 66 个约 20K 短请求随机混合，seed=7，统计 [2,4)s。沿用原始实验，不重新生成输入或执行结果。

- 橙线：预取窗口需求＝下一层读取量 / 当前层计算时间，含下一请求 L0；仅在当前计算窗口内累计，再在统一 2 ms 桶中平均。它是截止时间参考速率，不是当前请求常规 V/C，也不是队列积压量；等待期间该已过期预取窗口不再贡献橙线。
- 蓝线：真实服务或接收字节量 / 2 ms。整机图使用 SSD 服务，逐 NPU 图使用各卡链路实际接收，两者有传输时差。
- 整机灰虚线：盘容量 40 GiB/s。橙线越线表示该匀速参考需求超过容量，单独不足以证明任意截止时间集合不可行。蓝线峰值 40 GiB/s；无平滑、截断或限幅。

实际接收可在一个 2 ms 桶内高于参考需求：数据提前到达、后续用于计算。该图中的实际带宽/需求比不能直接当作 NPU 利用率。

`mixed8_bandwidth_simple_images.zip` 仅包含 7 张 PNG：三策略各一张整机图与逐卡图，另附 FIFO/Once 整机对比。

复现绘图：

```bash
python plot_bandwidth.py --font /path/to/chinese-font.ttf
```

数据来源：原实验 `mixed8_physical_bandwidth_20260914/data` 的物理桶与预取窗口。`data/audit.json` 保存源结果 SHA256、带宽峰值和字节守恒核验；全部 3000 个 SSD 桶及 24 组逐 NPU 接收量积分已验证。
