# 近似筛选结果的适用范围与后续否证

本目录所有 `approximate_only=true` 的结果都用于选候选，**不能写成原生 ASU 或 Once 的实验结果**。

## 整层原子入队模型已暴露相位误判

早期 `search.py` 读取 `phase_search/approx_phase_search.py`，把整层读取原子入队。它在四场随机输入的 `[2,10)` 利用率上与原生相差约 −0.08 至 +0.70 个百分点，但这不保证周期输入准确。

后续原生实验否证了其 I1、1:5、双群相位候选：整层模型预期约91%，实际长窗约96.56%。真实客户端按0.1微秒间隔逐块提交，交织与相位足以改变长期结果。**因此 `shortlist.json` 的周期排名已经不能直接作为优先级依据。** 保留这些文件是为了记录搜索路径和失败，不是保留预测结论。

## 逐块模型仍只是筛选器

`block_grid.py` 和 `conditional_grid.py` 读取改进后的 `phase_search/block_issue_probe.py`。它使用128-token块、精确尾块、0.1微秒提交间隔。对已验证的 I1、1:5 和1:8输入，前10秒的利用率与原生接近逐位吻合。

但它没有完整原生QoS策略状态、计数器、全部事件处理细节，且让有限pattern无限循环。不能用它替代原生长跑，更不能拿它计算Once效果。

## 20个双画像均低于2.5 GB/s的组合

固定1:8、前8卡offset4、后8卡offset0，筛选 A miss=3302/3328/3360/3400/3500 与 B miss=2448/2500/2600/2700 的20个组合。都保证任意16卡A/B组合名义欠载。

没有找到比 I1 更低的候选。I1 的逐块模型从 `[2,12)` 的93.461%回升到 `[2,60)` 的95.511%；另外两个延长候选回升到96.228%和96.587%。这意味着**短长窗约93%不一定已经达到长期稳态**，最终候选必须延长原生运行验证。

## 允许A高于2.5、依靠同时运行的A数量限制需求

搜索 A miss=2500/2600/2700/2800/2900/3000/3100/3200，B miss=2800/3000/3200/3600/4096，共40个画像组合。先筛初始8A+8B需求低于40的31组，再试请求数1:3、1:4、1:5，各两个相位，共186个输入。

只有10个输入在12秒近似轨迹中全程欠载且warm每卡都有A/B。最差是 A2500/B3600、1:5、offset3，`[2,12)`约94.866%；但延长60秒后出现330.972毫秒过载，利用率也回升到96.879%，因此**不能保留为长期持续欠载反例**。其余延长后仍欠载的候选最低约97.79%。

例如 A2800/B3000 的8A+8B确实欠载，但两组A会在某些时刻重叠；1:4、offset1的整条近似轨迹峰值为47.078 GB/s、过载约789毫秒，不能只凭8A+8B的静态组合把它叫作持续欠载。

这些结果不能证明不存在更坏的合法输入；它们只排除了这批画像和两群周期安排。后续若使用三群、四群或其他请求顺序，仍需要全程逐时检查。ASU和Once推进速度不同，**某条轨迹欠载不能自动保证另一个策略也欠载**。
