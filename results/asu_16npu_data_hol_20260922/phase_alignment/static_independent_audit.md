# 新相位校正输入：独立静态审计

本审计没有运行仿真，也未导入运行器的校验代码；直接用冻结 data 重算锚点、权重、C、V。名义欠载的数学检查通过，但低利用率及 warm 实际混合必须以完整原生结果为准。

| 项目 | 检查结果 |
|---|---|
| 拓扑 | 16 NPU、1 SSU，每盘40十进制GB/s |
| 画像 | 90个目录键、22种不同的总长度/miss；全部是网格内插值估计 |
| 请求 | 4688个；每卡53个A、240个B |
| 无空闲 | 序列仅含画像键；运行器固定arrival=0，没有delay/idle项 |
| 构造 | 真实相邻data锚点，非负权重且和为1；C按权重计算，V=(total−miss)×1408，无外推或缩放 |
| 校正请求 | 64个请求使用非标准A；总长度204637–204700 token，miss3304–3504 |
| 纯算覆盖 | 每卡81.293954–81.379040秒；60秒前不能因为请求耗尽而排空 |
| 名义需求上界 | 任意时刻每卡V/C≤2.489655335GB/s，因此16卡之和≤39.834485362<40 |
| 余量 | 0.165514638GB/s，仅0.413787%；不应忽略模型/测量误差 |
| warm每卡真实AB | 待原生层区间审计；序列含AB不能替代窗口实际覆盖 |
| 两策略同输入 | 正式config与本候选仅name不同；最终还需对ASU/Once的冻结manifest逐字节核对 |

名义需求的上界包括当前请求处于IO stall的时间，但按照历史约定不额外加入下一请求首层预取。它不保证所有预取任务的真实截止期可满足，也不是物理瞬时吞吐的上界。

与64秒失败候选相比，变化不止一个：旧每卡33A+264B、1A+8B短周期；新输入前缀3A+15B，之后五轮10A+45B，8张卡一组、两组顺序相反。新常规A段总共10个A，是首个校正A加9个标准A，不是额外加一个再运行10个。因而不能把结果差异全部归因于校正本身。

离线构造先用ASU近似模型得到每组首次A的计算开始时间，再选取真实网格内长度/miss，使较早开始的卡多计算一些，以便下一A重新接近同时开始。校正只存在于冻结请求内容中；原生重放没有在线反馈或强制等待。每卡比相同数量全标准画像多49.646–134.732ms纯计算量，工作量并非严格相同；该构造是定制压力输入，不代表一般随机业务。

## 快模型与原生已经发现的差异

14秒原生结果没有维持快模型预测的低水平，因此本次60秒预测不能当作结果。只读源代码和14秒raw证据表明：

1. 原生每个同刻提交轮次执行`submit_rng.shuffle(ready_npus)`；近似模型按heap插入序号解决同刻事件，没有相同的seed行为。同画像时卡身份可能近似对称，逐NPU定制画像会打破这种对称。这是需要定位的因素，不是已经量化的因果结论。
2. 近似模型用`SSD_free + 最后块字节/50GBps`作为HBM完成时间，没有逐NPU link队列。短尾块紧跟完整块时，虽SSD40低于link50，尾块仍可能等待上一完整块离开link。原生request18尾83token，逐块平均等待×块数÷8得到每层平均0.68288us；request1000018尾44得到2.05568us，恰与`max(0,176KiB/50GBps−tail_bytes/40GBps)`一致。这些微秒误差与离线相位对齐精度同量级，但目前没有隔离实验测出它们分别导致多少U变化。
3. 跨请求L0起读时刻没有发现这一类语义不匹配：14秒原生ASU完整raw中1152个非首请求的L0起读时间，全部精确等于前请求末层计算开始时间，与近似模型的安排一致。

原生提交随机化见冻结`continuous_batch_sim.py:3062`，真实link队列见`:3997`及`:4017`；近似模型的固定序号和简化尾块完成见`align_probe.py:50`、`:63`。本次不修改任何运行器或旧原始结果。

最终必须独立检查ASU/Once的[2,60)、[20,60)、[40,60)和连续2秒窗口、每卡AB计算覆盖及排空时间。有限60秒即使表现低，也不等于无限稳态或对时间噪声稳健。
