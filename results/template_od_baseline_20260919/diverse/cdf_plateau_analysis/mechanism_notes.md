# OD 的 CDF 平台：层时序证据

只读取 full 三个种子的正式 raw；没有重跑或修改原结果。主样本为 [2,4) 秒内接纳的 586 条请求，全部跟踪至完成。它们的完整层周期可能延伸到 4 秒之后。

平台主要位于归一化横轴约 **1.8142–3.5887**，不能说整个 1.5–4 都不增长。输入只选 miss=256/1024/2048/4096，缺少中间的 512 档；小 miss 与大 miss 的计算时间相差很大，读取量却相近。这使“TTFT / 纯计算时间”落在明显分开的区间。

## 带宽与等待的实际证据

下表的 B 是每盘“每层读取量 / 每层纯计算时间”；b 是完整内部层周期“实际读完的字节 / 实际周期时长”。单位都是 GiB/s。b 用所有对应内部层的总字节除以总周期时间，不能把它当作瞬时速率，也不是所有 NPU 的整机平均。

| miss 数量 | 请求数 | 每盘需求 B 的范围 | 实际内部层周期平均 b/盘 | TTFT/纯计算范围 | 内部层等待占全部 I/O 等待 |
|---|---:|---:|---:|---:|---:|
| 256 | 249 | 7.114–9.886 | 1.576 | 3.589–6.852 | 91.53% |
| 1024 | 181 | 1.912–2.513 | 1.577 | 1.074–1.814 | 82.57% |
| 2048 | 83 | 0.934–1.253 | 1.184 | 1.000–1.098 | 0% |
| 4096 | 73 | 0.438–0.621 | 0.593 | 1.000–1.050 | 0% |

实际 ratio>4 的 243 条请求全部为 miss256。miss256 和 miss1024 获得的周期平均供给接近，但前者需要的速率高得多，计算又短，因而同请求后续层持续等待。miss2048/4096 的内部 L1–L7 没有任何暴露出来的等待；其少量额外时延都来自跨请求首层 L0。

**1.25 GiB/s 是 OD 每盘每卡的 CIR 保证，不是硬上限。** 本次配置 PIR 不限，允许借用空闲份额。上表高需求两组已经获得约 1.576 GiB/s，实际单周期平均还会更高；所以“OD 被固定封顶到 1.25”不符合数据。问题是借到的带宽仍远低于 miss256 的 7–10 GiB/s 需求。

## 相同 128K，总耗时接近，归一化横轴却差很多

以下是各画像在三个种子中按 ratio 排序的精确中位样本。

| 项目 | 128K、miss256 | 128K、miss1024 |
|---|---:|---:|
| seed / request_id / NPU | 7 / 18000011 / 18 | 19 / 20000009 / 20 |
| 每层读取量（MiB） | 175.656 | 174.625 |
| 每层纯计算 C（ms） | 6.024 | 23.363 |
| 每盘需求 B（GiB/s，三盘平均） | 9.492 | 2.433 |
| 内部层周期平均时长（ms） | 38.639 | 34.400 |
| 周期实际 b（GiB/s，三盘平均） | 1.480 | 1.652 |
| 内部 L1–L7 总等待（ms） | 228.306 | 77.254 |
| 跨请求 L0 暴露等待（ms） | 0 | 23.478 |
| 8 层纯计算时间（ms） | 48.192 | 186.907 |
| 实际 TTFT（ms） | 276.498 | 287.638 |
| TTFT / 纯计算 | 5.737 | 1.539 |

两者都读约 175 MiB/层，实际 TTFT 也接近。右侧计算时间约为左侧的 3.88 倍，因此 SLO 的归一化分母也大约 3.88 倍。**CDF 横轴的大间隔，并不意味着两类请求的绝对 TTFT 也相差数倍。** 左侧确实有更严重的 I/O stall，但归一化分母的差异同样关键。

最简单的精确核对公式是：

```text
TTFT = 8 × C + 首层 L0 等待 + 内部 L1–L7 等待总和
归一化 TTFT = 1 + 总 I/O 等待 / (8 × C)
```

## b 的定义为什么可靠

逐个核对了 4,102 个内部层周期，均满足：

```text
周期起点 = 上一层开始计算 = 当前层开始读取
周期终点 = 当前层开始计算
周期时长 = C + 当前层暴露的 I/O 等待
b_s = 当前层在盘 s 上的完整读取量 / 周期时长
B_s = 同一读取量 / C
b_s / B_s = C / 周期时长
```

当前层全部数据在周期终点前已到达 NPU，SSD 服务也已完成；开始读取又不早于周期起点。因此完整周期内可以通过已知字节量与实际边界重建平均供给。这里没有保存逐块 SSD 服务日志，不能据此声称恢复了瞬时带宽曲线。周期恒等式最大误差约 4.3e-13 ms；TTFT 分解误差约 3e-12 ms。

同请求内部周期的 b/B 不直接等于整个请求的 1/ratio：请求还包括最后一层计算和跨请求 L0 等待，需使用上面的请求时延分解。

## 结论的边界

数据支持的机制是：OD 按 NPU 提供独立通路、相同保证份额，借用后的供给仍不足以满足高 V/C 的 miss256 画像；离散输入档位和纯计算归一化又把两个族群明显分开。三个 warm 窗口中，每盘实际供给都为 40 GiB/s，确有持续资源竞争。

这是这批输入和本次执行的结果，不是 OD 必然产生平台的定理。加入 miss512、改变画像比例、带宽容量或 SLO 基准，都可能改变曲线；本次没有验证这些反事实。原始数字、代表请求及源码/结果哈希见 `mechanism.json`，用 `python analyze_mechanism.py` 可只读复算。
