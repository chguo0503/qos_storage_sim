# 持续过载：OD 的 TTFT CDF 为什么有平台

这里核对的是模板增补实验 `full / od_baseline`，32 NPU、3 SSU × 40 GiB/s，seed 7、19、43。选入 warm `[2,4)` 秒接纳的请求，跟踪到完成，共 586 个；CDF 按三种子等权平均。

## 先读懂平台

横轴是 `x = (prefill 完成 − NPU 接纳) / 该请求 8 层纯计算时间`，不是仿真时钟。CDF 在某个横轴区间保持水平，表示没有请求的时延倍数落在这个区间。

原观察“1.5 到 4 倍有点平”需要细化：

| 横轴阈值 | OD 累计比例（三种子等权） |
|---:|---:|
| 1.5 | 38.9137% |
| 2.0 | 57.4614% |
| 3.0 | 57.4614% |
| 3.5 | 57.4614% |
| 4.0 | 58.4863% |

真正没有任何请求的开区间是 **(1.814230, 3.588659)**。1.5 到约 1.81 仍在上升；从 2 放宽到 3.5 倍，达标比例完全不变。3.5887 到 4 只有 6 个请求进入。

## 为什么请求会分成两群

输入有 24 个画像，但 miss 只取 **256、1024、2048、4096** 四档；总输入长为 32K、64K、80K、128K、160K、200K。每卡每个总长度的四档请求数为 3、2、1、1，独立随机打乱，未包含 miss=512 等中间档。

| miss token 数 | warm 入选请求数（合并计数） | 每卡每层需求 B=V/C（GiB/s） | 实测 TTFT/纯计算时间范围 |
|---:|---:|---:|---:|
| 256 | 249 | 21.34–29.66 | 3.59–6.85 |
| 1024 | 181 | 5.74–7.54 | 1.07–1.81 |
| 2048 | 83 | 2.80–3.76 | 1.00–1.10 |
| 4096 | 73 | 1.31–1.86 | 1.00–1.05 |

以上需求是一个 NPU 跨三盘的总需求，不是单盘需求。miss=256 的计算短，但仍要读大量已命中的 KV，所以需要很高的带宽才能把读取隐藏在计算中；其余三档的计算长得多，读取更容易被覆盖。

OD 每盘给每卡 1.25 GiB/s 的 CIR，仍可借用空闲份额，**这不是固定限速上限**。它没有为高 B 的卡自动提供与 B 成比例的带宽。在本次竞争状态下，短计算那档暴露出更多 I/O 等待，占其纯计算时间的倍数也大；较长计算的档位则停留在较小倍数。请求的分组和实际供给共同形成这次空档，不能只凭缺少某个 miss 档位就保证一定出现平台。

## 归一化分母也是关键

下面是两档 128K 输入中、各自处在时延倍数中位数位置的真实请求，并非改变一个变量的受控配对实验。

| 项目 | 128K / miss 256 | 128K / miss 1024 |
|---|---:|---:|
| seed / request ID | 7 / 18000011 | 19 / 20000009 |
| 每层读取 | 175.656 MiB | 174.625 MiB |
| 每层计算 C | 6.024 ms | 23.363 ms |
| 8 层纯计算时间 | 48.192 ms | 186.907 ms |
| 实测 TTFT | 276.498 ms | 287.638 ms |
| 横轴位置 | 5.737 倍 | 1.539 倍 |

两者的读取量和绝对 TTFT 很接近，但前者的纯计算时间只有后者约四分之一。因此，前者除出来接近 5.74 倍，后者只有 1.54 倍。**横轴相差很远，并不意味着绝对 TTFT 也相差同样倍数。**

内部 7 个预取周期的实测结果也相符：前者平均周期 38.639 ms，实际供给约 1.480 GiB/s/盘；后者周期 34.400 ms，约 1.652 GiB/s/盘。两者都借用了超过 CIR 的带宽，但前者每盘需求约 9.492 GiB/s，后者约 2.433 GiB/s。相近供给对这两档计算时间造成了不同的等待倍数。这里的供给是完整层周期平均，包括等待，不是瞬时盘速。

## 这个结论能推广到哪里

- 这是本次离散画像、配比、窗口和策略下的实测分布，不是 OD 在所有持续过载场景中必然出现的固定形状。
- 1.5 是统计阈值，OD 没有在这里执行特殊分流或截止判断。
- 加入中间 miss 档位，或者使用更连续的计算/读取画像，可能填补平台；这是待验证的预测，需要保持其他配置、负载和配比可比后再实验。
- 用绝对毫秒横轴重画，也可能呈现不同形状；归一化 CDF 回答的是相对纯计算基准的慢了多少倍。

本分析没有启动新仿真，也没有修改原图或原结果。
