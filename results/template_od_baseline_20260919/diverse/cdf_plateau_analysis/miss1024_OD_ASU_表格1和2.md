# miss=1024：OD 与 ASU 的每层读取对照

以下两表来自**持续过载 full24、random 输入**实验，不是持续欠载或局部过载实验。

- 配置：32 NPU、3 SSU，每盘 40 GiB/s，每请求 8 层，batch size=1。
- miss 固定为 **1024 token**；总输入长度包含这 1024 个 token，`1K=1024 token`。
- 样本：seed 7、19、43 中，在 warm `[2,4)` 秒内接纳的请求，跟踪至完成。
- 读取耗时：统计这些请求完整的内部层 L1–L7，从提交读取到数据在 HBM 到齐，包含排队和传输；不把层截断在 4 秒。三个种子的层样本合并取平均。
- 两策略使用相同的完整输入；因执行速度不同，各自在 warm 窗口接纳的请求集合可能不同。

**表中带宽均为单个 NPU 跨三盘合计的速率，不是单盘速率，也不是整机总带宽。**

## 如何读这两个带宽指标

```text
需求 B = 每层读取量 / 每层纯计算时间
有效读取速率 = 每层读取量 / 平均读取耗时

用表中的单位计算：
速率（GiB/s）= [读取量（MiB）/ 1024] / [时间（ms）/ 1000]
```

需求 B 表示希望把一层读取藏进一层计算时，需要的参考速率。有效读取速率则根据本次实测读取耗时反算，包含排队的影响；它不是盘正在服务时的瞬时速率，也不是按完整计算层周期统计的平均供给。

同一画像的每层读取量固定，因此这里的 `V / 平均读取耗时` 等价于这些层的 `总读取量 / 总读取耗时`，不等于逐层 `V/R` 的算术平均。

例如 200K 请求每层读取 273.625 MiB：OD 平均耗时 56.087 ms，对应约 4.764 GiB/s；ASU 平均耗时 35.073 ms，对应约 7.619 GiB/s。这里的速率是对结果的描述，不能再把它当作独立测得的原因，循环解释耗时。

OD 每盘每卡的 CIR 为 `40/32=1.25 GiB/s`，PIR 不限并允许借用空闲带宽，所以三盘合计 3.75 GiB/s 不是实际读取速率的硬上限。

以上趋势来自本次输入与竞争状态，不代表所有 ASU 实验的读取耗时都与读取量无关。
