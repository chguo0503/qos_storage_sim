# 同样输入，为什么 ASU 的 CDF 没有 OD 的平台

此前只强调 miss 档位和归一化分母，解释不充分。完整输入固定了每个请求的读取量 V、计算时间 C 和顺序，但策略改变了读取的排队及完成时刻，因此也改变了 TTFT 的分布。**离散输入本身并不保证输出 CDF 有空档。**

本说明只读复算已有 full 运行，不启动新实验。配置为 32 NPU、3 SSU × 40 GiB/s；取 `[2,4)` 秒接纳请求并跟踪至完成，seed 7、19、43。下表范围和计数是三个种子合并后的描述；原图的 CDF 仍按种子等权。

| miss 档位 | ASU 的 TTFT/纯计算范围 | OD 的范围 | ASU 落入 OD 空档的请求数 |
|---:|---:|---:|---:|
| 256 | 2.55–16.56 | 3.59–6.85 | 20 |
| 1024 | 1.00–5.07 | 1.07–1.81 | 60 |
| 2048 | 1.00–2.43 | 1.00–1.10 | 12 |
| 4096 | 1.00–1.31 | 1.00–1.05 | 0 |

OD 空档严格指 `(1.8142302266, 3.5886586782)`，ASU 有 **92 个**请求在这里。ASU 仍有计算长短导致的快慢倾向，但不同档位的输出时延范围发生重叠，把平台填平了。

## 共享 FIFO 如何改变这一分布

ASU 将不同 NPU 的 I/O 放进同一 Path。自己的读取量小，也要等待先进入队列的其他请求 I/O；排队时间并不按自己的读取量同比缩小。

OD 在每盘上给每个 NPU 独立 Path，盘在 Path 之间仲裁。小读取不必在同一 FIFO 中等待所有先到的其他卡 I/O 完成；在这次竞争状态下，它的读取完成时间更随自身读取量变化。OD 仍共享物理盘，仍会等待，也允许借用空闲带宽，不能说完全隔离或固定封顶。

对 miss=1024 的各画像，内部层的**平均读取耗时**（提交到 HBM 到齐，含排队）如下：

| 总输入 | 每层纯计算 | ASU 平均读取耗时 | OD 平均读取耗时 |
|---:|---:|---:|---:|
| 32K | 7.26 ms | 29.66 ms | 8.74 ms |
| 64K | 12.63 ms | 30.99 ms | 18.23 ms |
| 80K | 15.31 ms | 30.60 ms | 22.60 ms |
| 128K | 23.36 ms | 33.10 ms | 35.24 ms |
| 160K | 28.73 ms | 33.77 ms | 45.59 ms |
| 200K | 35.44 ms | 35.07 ms | 56.09 ms |

在 ASU 中，上表不同读取量的请求都受到约 30–35 ms 的读取完成延迟。各自计算时间却从约 7 ms 到 35 ms 不等，因此即使 miss 相同，归一化后的慢速倍数也很不同。特别是 64K/1024、80K/1024 这批请求，分别有 35、17 个落在 OD 的空档里。

OD 中，读取耗时随读取量变化得更明显；结合本输入的计算时间，使同一 miss 档位的归一化时延更集中。以上是本次 trace 的机制解释，不是所有 FIFO 工作负载都必然有相同的 30–35 ms 延迟。

## 同一个请求的直接对照

seed 43、request ID 16000007、NPU 16：总输入 32K、miss=2048，每层读取 41.25 MiB。这个请求在两策略中都落入 warm 接纳窗口。

| 指标 | ASU | OD |
|---|---:|---:|
| 每层纯计算 | 14.369 ms | 14.369 ms |
| 内部层平均读取耗时 | 32.420 ms | 9.111 ms |
| 7 个内部层累计 I/O stall | 126.355 ms | 0 ms |
| 全请求纯计算 | 114.953 ms | 114.953 ms |
| TTFT（接纳到 prefill 完成） | 241.308 ms | 114.953 ms |
| 横轴位置 | 2.099 倍 | 1.000 倍 |
| 单块平均 SSD 排队 | 31.500 ms | 4.472 ms |

ASU 的读取超过了计算可覆盖的时间，这个请求进入 2.10 倍的位置，恰好填在 OD 的平台里；OD 的读取可以藏在计算里。

原始日志中每个 I/O 块都是 176 KiB。“大读取阻塞小读取”是指多个先入队 I/O 块构成的队列积累，不能解释成某个更大的单块 I/O 不可抢占。这些结果没有保存完整逐块队列先后日志，不能据此点名某一个请求就是直接阻塞者。

## 排除一个容易混淆的因素

两策略的完整输入相同，但接纳时刻不同，所以原 warm cohort 分别有 ASU 589、OD 586 个请求。进一步只比较**两边都在 warm 窗口接纳的同一组 529 个请求**，ASU 仍有 78 个落入空档，OD 为 0。因此，平台差异不能仅用窗口选入集合不同解释。

ASU 也不是必然没有平台：只看本实验的 128K 子集，其 miss=256 位于约 3.68–6.40 倍，其他档位不超过约 1.76 倍，仍然存在间隔。混入其他总长度后，中间被填满。

平台形状也不等于策略整体优劣。例如同一个 200K/miss256 请求（seed43、ID12000008），ASU 为 3.845 倍，OD 为 6.282 倍。独立 Path 改变了大小读取之间的服务分配，并非给所有请求统一提速。
