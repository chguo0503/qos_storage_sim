## “按层”怎样计算

```text
一层周期 = 开始计算第k层 → 开始计算下一层
周期时长 = 第k层计算时间 + 等下一层数据就绪的时间

某张卡从某盘获得的平均带宽
  = 该盘在此周期内实际为这张卡读出的字节量 / 周期时长

某张卡对某盘的平均需求
  = 此周期内该卡V/C参考需求的时间积分 / 周期时长
```

下一层数据在本层计算期间预取，所以统计周期需要包含本层计算和随后的等待。不能仅用真正读取的那几微秒作分母，否则会漏掉等待和没有服务的时段。

每张卡按自己的真实周期求平均，再把同一时刻32张卡的平均值相加：逐盘图对同一块盘求和，整机图对三块盘再求和。需求和供给都使用同一张卡的周期边界。同一请求内的需求通常不变，跨请求周期可能切换画像，因此用时间积分处理。

跨请求时，上一请求末层会预取下一请求首层，真实服务量计入周期；不能把它仍当成上一请求的读取量。

**窗口两端也先用完整层周期计算均值，再裁出 `[2,4)` 的显示部分。** 不把最后剩下的零点几毫秒另当成一整层。因为首尾层周期包含部分窗外时段，图中曲线在2秒内的面积可能与物理设备在这2秒里实际服务的字节量略有不同；图上分别标出“完整周期曲线均值”和“物理warm均值”。差异只能来自窗边周期，内部周期严格守恒；NPU利用率与CDF仍使用原先严格的 `[2,4)` 口径。

## 如何读新蓝线

蓝线是**各卡完整层周期平均供给相加**，不再是10ms内的瞬时服务均值。不同卡的平均区间并不对齐，因此相加后的局部值可能高于40 GiB/s/盘或120 GiB/s/整机；这不代表物理SSD超速。容量虚线是物理设备容量，不是这种异步平均叠加值的逐点上限。

粉色背景仍来自原始逐盘参考需求的精确事件区间。持续过载、持续欠载、局部欠载的分类不因为平滑而改变，也不根据新蓝线是否越过容量线判断。

本次供给计量位置沿用原图：**SSD开始服务到SSD完成服务**，不混入后续NPU接收链路的传输时间。请求首层预取的物理字节计入供给，但未接纳的下一请求不重复算成第二份活跃请求需求。

对于同一请求内部的完整周期，恰好读完下一层所需数据，才可写成 `平均b = V / 周期时长`。跨请求、窗口裁边以及32卡汇总后，不能直接拿总供给/总需求代替NPU利用率。

## 数据来源与核验

原日志保存了全盘10ms服务量和逐层时刻，无法精确恢复每张卡在任意裁边周期内收到的服务量。本次保持原输入、原策略、原seed及原模拟器，重放六个seed 7场景，旁路记录每张卡、每块盘在每个周期内的真实服务字节。

重放同时保留完整周期、实际窗内裁片两套精确字节积分。后者用于核对原10ms和整窗实际量，不用于主图的层均值。重放校验包括输入与源码哈希、原始请求/层时序、NPU利用率、SLO、原10ms服务量、每卡每盘整窗服务量，以及完整周期的下一层读取量守恒。重放只补充测量，不调整输入或策略；旧PNG、CDF和利用率结果保留。

三组画像配比不同，这仍是三类已有输入的描述性对比。SLO采用接纳到prefill完成的代理耗时，不含接纳前排队。
