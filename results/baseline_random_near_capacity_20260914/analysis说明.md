# 独立分析接口与口径

本目录 `analyze.py` 只读取完整仿真结果，不运行仿真、不修改输入或核心代码。它不假定 A/B 的具体长度、计算时间或读取量；角色取自每条请求的 `load.role`，支持 L、S、S1、S2 等。

```bash
python results/baseline_random_near_capacity_20260914/analyze.py \
  --case CASE_DIR --output CASE_DIR/analysis.json --short-role S
```

Python 接口为 `analyze_case(case_dir, windows=None, short_roles=None)`，返回可以直接保存成 JSON 的字典。默认统计 `[2,4)` 秒、`[2,20)` 秒及 `[4,6)` 至 `[18,20)` 的每个两秒窗口。可重复传入 `--window 2000:4000` 自选窗口；输出路径必须位于本次新研究目录内。

输入至少需要 `manifest.json.gz` 与 `result.json.gz`。如存在 `command.json`，必须已完整完成且来源 SHA 匹配。使用仓库标准 `load_manifest` 核验冻结输入指纹，所有请求必须已运行到最终完成。每请求 batch=1，32卡，层数和盘数从日志读取。

每个 `windows[]` 中的主要字段：

| 字段 | 解释 |
|---|---|
| `U_percent` | 窗口内真实计算卡时间 /（32 × 窗口长度）；等待、空闲和提前结束仍留在分母里 |
| `per_npu` | 每卡计算、等待、空闲、整窗是否有请求，各角色实际计算和占用时间 |
| `mixed_card_count` | 窗口内实际计算过所有输入角色的卡数；角色短暂出现但没计算，不算 |
| `long_short_mixed_card_count` / `long_short_mixed_pass` | 每卡计算过至少一种指定短类和至少一种其余长类；L/S1/S2 时只要求 L 加任一种短类，不要求两个短亚类都出现。pass 仅表示32卡都满足混合，整窗有任务另看 `all_32_active` |
| `classes` | 每角色计算/已接纳占用时间、角色利用率、卡时间占比、对整机U的贡献及首层/内部层等待 |
| `internal_layers_released_in_window` | 预取发出时刻在窗口内的内部层；跟踪到数据到齐，包括零等待样本和窗末后完成的样本 |
| `complete_internal_cycles_inside_window` | 当前层计算开始到下一层计算开始都位于窗口内的完整内部周期 |
| `nominal` | 按每次接纳/完成事件精确扫描的逐盘当前请求 V/C：峰值、均值、超限时间及峰值时的请求证据 |
| `physical` | 若有物理服务文件，给出逐盘实际忙时、读取带宽、每卡实际接收带宽以及服务量与接收量的差值 |
| `slo` | 接纳时间在窗口内的请求，以最终 prefill 完成延迟检查 SLO×1.5 和×2；同时给各类别分母/达标数 |

短类优先使用显式 `--short-role`（可重复，合并 S1/S2），其次取 metadata 的 `short_roles`；未指定时只识别约定名称 S、S1、S2 等。不会猜测 A/B 哪一个是短计算：旧 A/B 参考应显式指定 `--short-role A`，此时 B 为长计算。没有可识别的长/短两组时，二分类混合指标为 null。

内部层有两种平均利用率：逐层 `C/(C+stall)` 的简单平均，以及 `sum(C)/sum(C+stall)` 的时长加权平均。它们都不等于已接纳请求类别利用率，也不能替代整窗32卡实际计算时间统计。`stall_ms_including_zeros` 的分母包含所有入选内部层，不能只平均发生等待的层。

`work_implied_mean_b_GiB_s_weighted_by_cycle_duration` 是层工作量除以这些完整周期时长，来自同一次执行的记账关系；没有逐块 trace 时，不声称是独立测得的带宽分配能力。`physical` 中的接收带宽则来自实际链路服务区间。

逐盘名义需求只计算当前已接纳请求的实际每层落盘字节 / 计算时间，不额外把下一请求的首层预取加一遍。这里沿用已有请求参考需求口径，并非声称这些值就是每瞬间新产生的物理流量。只有各盘在每个正时间间隔都不超限，才可标记逐盘欠载；总体平均接近容量不能证明这一点。若同一请求各层的逐盘读取量不同，分析会明确拒绝，不悄悄平均掉层间差异。

`physical_service.json` 的两秒 bin 只能精确聚合成以现有 bin 边界为起终点的窗口，不能据此还原任意局部时刻的带宽。分析记录 SSD 累计服务量减 NPU 累计接收量在窗口前后的变化；窗口内两者不相等可能来自边界存量，不能立即视为字节丢失。

SLO 主指标是“最终 prefill 完成时间 − 接纳时间”，阈值是 `alpha × own_compute_ms`。这是 prefill 完成延迟的 TTFT 代理，不是真实首 token 事件，也不包括接纳前客户端排队。窗口末尚未完成的入选请求跟踪到最后，不删除。另列同一接纳样本按外部到达计时的结果，以及窗口内新到达样本的结果；无样本记为 null，不写成0%。不同策略推进速度改变窗口接纳样本和类别占比，应同时查看分母。

空闲、类别未覆盖和名义需求超限是保留在结果中的实验事实，分别写入 `warnings`，不会作为技术错误丢弃。技术校验失败才会终止。
