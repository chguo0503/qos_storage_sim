## 结论与证据等级

**事实：已有实验不能支持“data 中的 Baseline 不会降低利用率”。** 它们只表明：已测的可行四画像与预先筛出的 33 行独立均匀抽样，在指定暖窗内没有明显降低设备 U。全 84 行抽样本身已有 Baseline 暖窗 U 96.15%–98.57%、SS 暖接纳 SLO 明显较低的结果，但不满足全程名义欠载，不能当作欠载反例。

**数学事实：原始 data 中存在含 SS 或较短 SL 的固定角色混合，能保证每盘全程 current V/C <40，同时允许一波 Long I/O 的服务工作远大于 Short 的单层计算。** 原 33 行筛选不是这类输入的完备判定器。

**推断：先前可行四画像对“原始数据是否也能产生同类 FIFO 损失”的检验偏保守。** 更准确的说法是，它为同时满足原每卡混合、短纯 C 份额近似匹配、完整配额、原验收窗口等条件，选用了每卡任意当前画像组合都安全的低 V/C 集合；不能仅归咎于 exact-cohort 算法。代码没有穷举所有 raw 画像、并发角色配置和相位，因此也不能说已经找到最有代表性的 raw 反例候选。

**须由后续结果核验：上述合法固定角色输入是否真的形成持续排队、具体降低多少设备 U、Once 是否改善。** 数学证书及假设突发工作量都不能代替真实层时序/逐盘服务轨迹，也不能承诺下降 10%。本审阅完成时主代理已启动新 pilot；此处的未覆盖判断针对历史两组，而非否认新产生的结果。

## 高设备 U 可能掩盖什么

设备 U 是暖窗实际计算区间总长 / (32×2000ms)；不是请求等权的 `8C/(completion−admission)` 平均，也不是 SLO。原始 84 行每行等概率时，目录纯 C 权重为 SS **1.094956%**、SL **16.098122%**、LS **4.858773%**、LL **77.948149%**。这是目录理想计算加权，不声称等于某个有限暖窗的实际类别占比。

对应实测中，Baseline SS 暖接纳 SLO 的五 seed 均值仅 **49.8407%**，LL 为 **100%**；Once SS 为 **89.0290%**。暖接纳 SLO 为接纳发生在 [2000,4000) 的请求，跟到完成，`completion−admission≤1.5×8C`。所有请求 arrival=0，该值不包括入卡前排队，不能叫用户到达后的真实 TTFT。全 raw 目录还有 20 行自身 V/C>50GiB/s，9 行由接纳后的链路下界 `7V/50+C>12C` 就可判定 SLO 不可达；不能把这些违约全算成 Baseline FIFO 的损失。

因此，“请求中 SS 有 12/84”不等于“SS 占用设备时间 12/84”，而“平均 97% 计算利用率”也不等于“短请求都表现好”。

## 可行四画像为什么弱化原短计算/大读突发的反差

四画像主组确实全部来自原始行，但不仅移除了外推：

- Short C 从原 0.528/0.697/0.899ms 升至 **7.257/9.942/12.626ms**，增加 13.75–14.26 倍；Long C 为 28.732ms，Long/Short C 比从 28.48–48.52 降至 **2.276–3.959**。
- Short V 增加 35.43–100.8 倍；Long 在完整输入总字节中的占比从 77.27% 降至 36.05%。这改变了每波读的来源和长短工作量比。
- 原 Short 是 SS，新 Short 全为 **SL**；Once 的允许 Path 池由 96 变为 32。最近键诊断的第三短画像 32K/512 也已是 SL，不能称它完全保持原分类。
- 5ms 快照相对于短 C 从 5.56–9.47 倍变成 0.40–0.69 倍。算法同名不意味着这个相对时间尺度不变。
- 为匹配约 67.47% 短纯 C 份额，packet 从 `L+(S1 S2 S3)×25` 改成 `L+(S1 S2 S3)×2`；每卡人口从 608 变为 49，long 从 8 变 7，exact-cohort 实际切点/相位也变化。

这些改变合理地构成一个 raw 外部有效性对照；它们不能单独归因为“data 的真实 C 使 Baseline 永不堵塞”。原三种最近 Short 的纯 C 加权 V/C=18.571974458GiB/s。若每卡完整人口与原短纯 C 份额 67.47% 都固定，换入低速 Long=192K/2048 或 /4096，理想平均容量要求短纯 C 份额分别不超过 25.3065% 或 33.7616%。这解释了为何坚持高短 C 份额时选型被推向 NQL 更大、C 更长的 Short；该条件是平均工作量必要条件，不能代替逐时刻约束。

## 名义欠载与突发干扰在数学上可以同时成立

令 C 以秒计，v[n,p,s] 是 NPU n 的画像 p 在 SSU s 上每层实际物理字节量（GiB）。研究定义的当前需求为

`D_s(t) = Σ_{当前已接纳且未完成的 n} v[n,p_n(t),s] / C[p_n(t)]`。

它不是瞬时实际 I/O 到达速率、SSD 服务速率、队列长度，也不包含下一请求额外 L0 的叠加。固定角色时一个充分证书是

`Σ_n max_{p属于该卡允许目录} v[n,p,s]/C[p] <40，逐盘 s 分别成立`。

若每种画像按 176KiB 条带，未知起点时可再用 `ceil(blocks_p/6)×176KiB` 上界；这是更保守但易审计的证书。已知物理 placement 时应直接求各盘向量，不能把六盘平均当最热盘。

核心在前一层开始计算时释放下一层读取；上一层 C 结束后若数据尚未就绪便等待。设 N_L 张 Long 的一层在同盘形成一波先行 FIFO 工作，该波纯盘工作为

`W_L,s = Σ_Long v[L,s] / 40`。

存在 `C_S < W_L,s < C_L` 与 `D_s<40` 同时成立的原始画像。前者表示在**先行工作确实排到短 IO 之前的条件下**，Short 隐藏预算小而 Long 隐藏预算大；后者限制的是除以各自 C 后的名义速率。两者不矛盾。Baseline 在每个 SSD 的 Path0 排队；不是六盘共享一条全局 FIFO，Long 的计算本身也不会阻塞 Short。短请求 read lifetime 还含提交、排队、SSD 和接收链路，不等于盘连续忙时长。

## 固定角色后必须重新解释的旧验收条件

1. **每卡暖窗有长有短不再适用。** 固定角色是另一个实验问题，不能把新纯角色卡判成构造失败，也不能声称它满足原每卡混合约束。
2. **第四请求≤1500ms 对上述原始 Long 从纯计算就不可能。** 200K/2048 的四请求最低 `4×8C=2263.697211ms`；192K/4096 为 4350.946591ms。若仍强制该条件，就会先验排除低名义速率的大 V/长 C Long。应保留为诊断，并预先采用适合固定角色的稳态判断，如全暖窗 active、层循环计数/不同固定窗口敏感性；不能实验后因数值不好移窗。
3. 每卡纯 C 总量>4s 足以排除暖窗前耗尽输入，但不保证相位稳态，也不保证暖窗每种画像出现。第一行纯 C 超 4s 至少需要 Short 136 请求、Long 8 请求（实际可用统一更长预算）。人口完整跟到结束，设备 U 与尾部 idle 分开。
4. 少量 SS 卡即使损失很严重，也会被多张满计算 Long 卡稀释。若 Long 暖 U=100%，则 `U_fleet=(N_L+N_S×U_short)/32`。5 Short 的极端全部不计算也最多贡献 15.625 个百分点；该上限不是可达性预测。不能用很高的 Short stall 倍数宣称整机必有大幅下降。
5. 固定角色、固定画像是一种机制控制，随机排序和多 seed 并不自动代表真实业务。变化画像、随机初始相位/到达、角色轮换都属于额外、需明确标记的新实验。

## 新 runner 审阅前必须保持的接口与边界

- 构造仅从 `ast.literal_eval(data)` 精确键读 C/V，`C_ms=原 per_layer_us/1000`；保留原 C、V、category、role 分开，逐块核物理 placement。NQL64 的半块须预先说明处理方式；上述候选没有该尾块问题。
- 输入冻结在两策略前，Baseline/Once 必须共享同 manifest fp、submit_seed、原 NPU/placement、层数、到达、窗口与全部请求人口。使用 **once**，不是 new_once。`shared_path_adapter` 的 Once 使用 5ms 采样快照；Baseline 同 wrapper/同静态 QoS，但 Path0 决策不查询压力，不应称 Baseline“根据 5ms 反馈调度”。
- 固定 NPU 绑定需显式 `--assignment fixed`；避免复用旧原输入人口常量 19456、旧 profile/class 断言、旧 each-NPU-mixed 或第四完成判定作为主结果剔除器。
- 若比较只改角色绑定，保留旧 physical placement，而不是根据新 NPU 悄悄重条带；若这是新 raw 人口，应明确其与旧 synthetic 人口不同，按新绑定创建 placement 合法，但两策略内必须完全相同。
- capacity 判定须用完整执行中 admission→completion 的正时长状态，逐盘实际 V/C 累加，零时刻 complete/admit 批量处理；跨请求额外 L0 按既有定义不计，但这一遗漏必须在解释中保留。另核 50GiB/s 每卡链路。
- 主结果分别给设备 U、短卡 U、长卡 U、暖接纳 SLO（追踪到完成）、完整人口与 makespan。保留所有 seed/失败科学条件，不重采样、不静默剔除、不用候选测试阶段均值充当预定五 seed 复验。
