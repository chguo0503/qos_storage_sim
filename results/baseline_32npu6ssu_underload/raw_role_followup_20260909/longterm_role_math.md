# 长期反复切换角色：离线数学候选

本文件只提出和核算输入，不运行模拟器，也不把预测当成结果。数值由 `python -B longterm_role_math.py` 直接解析原始 `data` 复算，完整精确值和来源哈希在 `longterm_role_math.json`。原始短画像为 32/48/64K、NQL1024，真实类别均为 SL；长画像为 160/176K、NQL1024，类别 LL。所有请求总输入严格大于 10K，不缩放 C/V，不补零块。

旧 v8 三倍队列在第二轮不再低 U：前20卡内部 Long 释放时刻模 C 的覆盖圆弧由 0.050454ms 变为 21.760251ms，实际 Long 数和短画像组成也改变。短类自身计算/占用从 75.7383% 恢复到 99.7736%，所以不能仅靠“每卡反复长短混合”保证长期损失。来源为 `window_sensitivity/repeated_queues/repeated_mechanism.md/json`，并非本脚本新结果。

## 两个16卡群组交换角色

使用 L=160K/1024、S=32K/1024；各群组内部每轮使用完全相同的画像序列。NPU0–15 从 Long 段开始，16–31 从 Short 段开始。候选一前组重复 `[4L,12S]`、后组重复 `[12S,4L]`，各8遍；候选二对应 `[8L,24S]` 和 `[24S,8L]`，各4遍。两候选每张卡均有同样32L+96S，总纯计算12928.963114ms，可保证12秒前不会耗尽。它们是单一 Short 画像的机制探针，不满足额外“多种短画像”的要求。

长层 C=28.732067426ms，短层 C=7.257231579ms。16张 Long 一波完整层的单盘服务工作为14.233398438ms。旧 fixed16 单短 Baseline 的短卡计算/占用为75.6387%；假设每个 Long 层周期内 Short 稳定完成3个计算层，则短卡 U=3Cs/CL=75.774897833%，两组平均 U=87.887448916%。这使4个 Long 请求的32层与12个 Short 请求的96层可能在接近同一实际时长919.426158ms后交换角色。8L/24S 将该时长加倍，用于观察更少交接是否更能维持组内集中。

这不是预先规定实际计算起点。所有请求 arrival=0，没有定时切换、barrier、额外空等或状态复位；下一层由真实计算起点释放。跨请求 L0 的读取、同刻发块顺序和组内排队差异可能使上述3:1关系失效，故87.89%既不是定理也不是已测 U。该组原始160K层含1272=6×212块，每盘量相同；允许所有32张卡任意选择 L/S 时，每盘名义上界均为39.630697580GiB/s，接收链路最大7.430755796GiB/s。此证书也覆盖换角色重叠，且不依赖条带偏移。

## 各卡保留主要角色，但周期性处理另一角色

配合主进程的多短画像候选：使用 L=176K/1024、S1/S2/S3=32/48/64K、NQL1024。前16或20卡重复 `[8L,S1,S2,S3]`；其余卡重复 `[22S1,S2,S3,L]`。每个群组内部保留相同短段顺序，避免已知的独立短画像排列使返回 Long 的相位散开。两群组周期不同，彼此相位仍可能漂移；组内相位集中和实际长期 U 仍需检查。

长组每周期纯 C=2249.248890ms，其中 Short 占10.607900%；短组每周期1709.144328ms，其中 Long 占14.705098%。这些是完整配额的纯 C 份额，不是实际占用时间或任意窗口的份额。初始8L纯 C=2010.650820ms，因此不能由队列配额保证每个2秒滑动窗口内每卡都计算过两种角色。若需要长期每卡反复切换并且两个角色都贡献有意义的计算，应直接报告完整[2,12)角色正计算、切换次数，同时保留各2秒子窗。

这轮可以新建条带 `SSU=(block+npu)%6`，不同于旧 v8 保留来源请求的物理 placement。对每张卡每个盘，在四个允许画像中先取 V_s/C 最大值，再跨32张卡求和，逐盘上界为 `[39.893507756,39.898850398,39.893507756,39.888165114,39.888165114,39.888165114]` GiB/s。最热盘严格低于40，最大接收链路7.479698789GiB/s；因此这个明确的新 placement 下，任意角色重叠甚至32卡全 Long 都有名义欠载证书。16/20个Long同波的最大单盘完整层服务工作分别15.668488/19.587708ms，但不能将整波工作视为某一请求独占盘的连续时间。

## 必须区分的检验

主进程与审计代理负责真实模拟；本文件没有启动任何新作业。建议预先固定[2,12)主窗及[2,4)、[4,6)、[6,8)、[8,10)、[10,12)子窗，分别报告设备 compute/stall/idle、32卡活跃性、每卡两角色正计算和切换次数。为判断持续阻塞，另看组内 Long 释放模 C 的圆弧、Long 读是否被 C 遮住、Short 各画像的条件 U；不可只看整机平均。

名义欠载限制当前请求的 V_s/C，并不限制瞬间新释放的完整工作量，也不保证每层截止时刻可行。next-request L0 按既定口径不额外加入名义和，但实际模拟不能去掉它。容量证书不依赖策略，FIFO 的相位论证却不能直接套用 Once。若比较次序效果，随机对照必须保留同一新绑定每卡完整人口和每个请求的 placement，只改变顺序；新 placement 或配额不能借旧 v8 随机结果充当唯一对照。
