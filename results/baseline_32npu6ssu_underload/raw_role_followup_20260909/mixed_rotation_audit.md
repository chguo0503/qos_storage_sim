# 原始 1172 请求人口的每卡长短轮换：可行性与审计边界

本页仅做数学设计和既有层日志只读分析；没有运行仿真、修改 C/V、插入 sleep、修改共享输入或策略。设计与 design_stress 分工沟通；本页不生成其 runner 或 manifest。

## 结论

**有可行的队列构造空间，但“每时刻恰好20长/12短”不能由静态请求顺序保证。** 可把同一个 mixed manifest 的每卡完整人口重新排列成较长的 Long 连续段和 Short 连续段，用 8 组×4 卡的循环相位使角色逐组轮换。每次仅更换 4 个 Long 角色，理想情况下还有 16 个 Long 保持原来的层相位。

这样既保留每卡长短请求，也更接近固定角色的持续 Long 波。可是 Short 执行时间取决于当前队列，Long 首层又可能受前驱 Short 的预取预算影响，所以卡内索引不是时间屏障。必须从完成后的真实事件核验角色并发、相位、名义需求和暖窗两角色计算；不能把设计标签或按 C 预测的时间当成测量。

## 1. 不能混用的三个比例

当前 raw200_three_l20 的全局人口为 Long 380 条，S1/S2/S3 各264条；每层 C 分别是：

|画像|角色/路由类别|每层 C ms|每请求 8C ms|
|---|---|---:|---:|
|32K/1024|S1 / SL|7.257231579|58.057852633|
|48K/1024|S2 / SL|9.941586459|79.532691672|
|64K/1024|S3 / SL|12.625940760|101.007526083|
|200K/1024|Long / LL|35.442950938|283.543607501|

全人口 Long 纯计算为107746.570850 NPU·ms，Short纯计算62989.890583 NPU·ms。因此全人口 Long **纯 C 份额**为63.1069485%。它不是执行过程中 Long 的 active 时间份额。

定义固定暖窗 W=[2000,4000)：

- `A_L=Σ请求 |[admission,completion)∩W|`，只对 Long 求和；`A_S`同理，包括接纳后的等待。
- `C_L^W`、`C_S^W`是对应角色的真实层计算与 W 的交集，不能把完整8C算入被窗口截断的请求。
- 全32卡始终 active 时，`A_L+A_S=64000 NPU·ms`，平均 Long 并发数为`A_L/2000`，设备 U=`(C_L^W+C_S^W)/64000`。
- 角色的 pooled U 是`u_L=C_L^W/A_L`、`u_S=C_S^W/A_S`。每卡 mixed 后这是角色占用时间上的条件效率，不是固定几张 Short 卡的设备 U。

既有 fixed seed7 Baseline 暖窗给出 `u_L=1`、`u_S=0.6947382142`。若轮换按全人口 C 比例稳定遍历、且这两个效率能迁移，估计

`f_L,active = f_L,pure / [f_L,pure + (1−f_L,pure)/u_S] =0.5430400893`，

对应 **17.3773 张 Long**，不是20张。该式是稳态比例估算，不是有限暖窗测量，也不证明新队列会保持原 u_S。

反过来，若希望暖窗平均20 Long、12 Short且效率近似原 fixed，那么 Long 需计算40000 NPU·ms，Short约16673.717141 NPU·ms，暖窗 Long 纯 C 份额约 **70.57945%**。所以需要把较多 Short 留在窗前/窗后；这是同人口的窗口组成重排，必须披露，不能宣称暖窗仍按全人口63.11%的纯 C 比例取样。

## 2. 一个可直接构造、不会提前撞到尾部的周期核心

从已经冻结的 `raw200_three_l20_mixed_seed7` 出发，保持每卡所有请求身份、C/V、arrival、NPU绑定和逐块 SSD placement 不变，只重排该卡队列。每卡有 Long11/12条，三种Short各8/9条。令

`T=8C_Long=283.5436075005082ms`。

建议先构造一份画像模板：

`P = L,L,L,L,L, S3,S3,S1,S2,S2,S2,S3`。

每卡提取两份 `P²`，总用 Long10、S1两条、S2六条、S3六条；所有现有卡都具有足够配额。用该卡真实请求逐画像填入，不能克隆请求。每卡剩余请求按既有相对次序追加在核心之后。

**只循环切 `P²`，再追加余量。不要把包含尾部余量的全队列一起循环切。** 后一种做法会让相位较后的卡提前遇到非周期尾部，破坏暖窗轮换。两份核心的纯 C 为

`2×[5T+8(C_S1+3C_S2+3C_S3)] =4034.793086805ms >4000ms`。

因此不论策略是否产生 stall，余量请求都不能在4秒前被接纳或计算。这是关于完整输入数量和时间下界的保证，不是关于暖窗相位、并发数或利用率的保证。核心后的余量仍须完整执行并计入最终人口、SLO和 makespan，不能丢弃。

额外注意：仅有“核心纯C>4秒”一般不能排除最后一层提前预取尾部L0。对本模板可再加一个独立下界：所有arrival=0，第一请求L0至少要经本卡50GiB/s链路，最小耗时`V_min/50=0.832519531ms`；最后一层C至多35.442950938ms。因此尾部L0最早释放时间不小于`4034.793086805+0.832519531−35.442950938=4000.182655398ms`，也在暖窗之后。该余量很小；如果改模板、C或预取规则，需要重新计算，不能泛化为纯C条件自然覆盖所有额外I/O。

分8组，每组4个 NPU，组内使用同一画像模板。按核心请求索引选切点

`[0,1,2,3,4,5,7,10]`。

前5组从 Long 段不同位置开始，初始20个 Long 角色；后3组从 Short 段开始，初始12个 Short 角色。虽然画像顺序相关，填入的每条原请求及其真实 placement 仍不同；不能假装它们是完全相同的物理读。

这是一种明确的人工相关顺序，适合检验机制，不能称为真实业务或独立随机到达。对照应是同一个 frozen mixed manifest 的原随机顺序，而不是重新分配另一批请求。新位置 request_id/generation 可以重编号，但必须保留能回溯原 mixed 身份的映射；原 `original_request_id/source_original_npu_id` 仍标识更早固定人口的来源，不应覆盖丢失。

## 3. Short 段为什么这样选：已有测量与推断分开

只读取 `raw200_three_l20_fixed_seed7/baseline` 的微批日志，选择 admission≥2000且completion≤4000的完整 Short 请求，得到：

|画像|完整请求数|平均接纳到完成 ms|该样本最小/最大 ms|按所有暖窗交集计算的角色 U|
|---|---:|---:|---:|---:|
|S1|59|95.596140652|83.426841 /102.522443|61.072073%|
|S2|61|113.470157579|107.022060 /128.653054|70.415576%|
|S3|72|137.670191743|123.822833 /145.999155|73.516025%|

后三列来自不同统计人口：平均/极值使用完整落窗请求，U使用所有窗口相交请求的裁剪时间。以上不是新顺序的性能预测区间。

用三个完整请求时长均值作粗略线性设计代理，模板的一个 Short 段为

`1×95.596140652+3×113.470157579+3×137.670191743=849.017188618ms`，

接近目标 `3T=850.630822502ms`。此时周期约 `5T+849.017=2266.735ms`，Long 段1417.718ms、Short段约849.017ms。理想8相位角色轮换接近20/12。

三个初始 Short 后缀在该代理下分别剩849.017189、573.676805、251.140349ms；相对最近24、16、7个 Long **层**周期的偏差分别−1.613634、+6.589590、+3.039693ms。这里既要看请求周期T，也要看层周期C_Long：Short段长度差接近整层C时，角色交接时刻可能早/晚一层，而 Long 内部读释放仍可能在模C意义上相近。

**这些均为设计推断。** 请求处理时长不具有跨排序不变性：Short前驱画像变化、队列交织、已发送/未完成工作、接收链路都会改变它。Long从Short切入时，首层L0仅在前驱Short最后一层计算开始时预取；Long首层因此可能错过原有Long波。不能人为把它延迟到理想时刻、插入sleep、重置相位，或把自然晚到的请求偷偷改arrival。

如果实际每个 Long 连续段仍少于2000ms、每个 Short连续段也少于2000ms，且整个暖窗位于周期核心，则任何完整2秒窗都不能只覆盖一个角色连续段。这对暖窗每卡混合有利；不过某角色可能刚接纳、尚在等待而没有正计算，因此最终仍要逐卡核验两类正计算，不能只看active身份。

## 4. 同输入两策略不可能自动保持同一20/12比例

模板核心 Long 纯 C 份额为 **70.2746340%**。若 Once 将 Short等待几乎消除，则一个 Short段只需599.678506ms，理想周期为2017.396543ms，稳态等效 Long并发约 **22.487883张**。如果 Baseline 的 Short段接近849ms，它才接近20张。

角色并发是策略执行速度的结果，不是这个 open-loop 队列能精确固定的外部控制变量。公平比较要求两策略输入相同，允许它们自然产生不同的角色轨迹；不能为了强行都维持20/12而给某策略加暂停、换队列或重绑。应分别报告两策略的实际 `K_Long(t)`。

## 5. 逐盘欠载：20张Long只是设计目标，不是安全证明

保持实际物理 placement 时，各原始画像最热盘的保守单卡名义值为：

|画像|最热盘 V_s/C GiB/s|
|---|---:|
|S1|0.971384262726|
|S2|1.063647222089|
|S3|1.116678856750|
|Long|1.259692424469|

若全32卡active、当前Long数为K，则一个简单充分界是

`D_s ≤ K×1.259692424469+(32−K)×1.116678856750`。

K=20时≤38.593994770，K=29时≤39.881116880，均小于40。K=30的这个最大组合界为40.024130448，仅说明该粗证书不通过；不能一概认定实际K=30就过载，因为真实Short画像和盘上余块分布可能更低。K=32时总需求必超过6×40。

因此可以容许一定交接时差，但不能只报告平均Long数接近20就宣称全程欠载。必须按真实admission→completion每个正时长区间，累加实际逐盘V/C，保留最热盘峰值见证及超限时长。next-request L0照原研究约定不额外计入这项名义约束，但其实际I/O仍完整仿真；名义欠载不是无突发或无排队证明。

换相位、重排之后每卡可用画像和placement集合没有变化，所以原 mixed manifest 的通用静态界也不会改变。那个界略高于40不妨碍某条实际执行轨迹始终欠载；要用上述数量界或完整事件扫描补证，不能拿原固定20/12输入的静态界直接套在混合卡上。

## 6. 验收项：避免把新约束换成较弱概念

1. **同每卡人口。** 新 ordered 与原 mixed random 逐原身份一一对应；除位置ID/generation外，NPU、C/V、arrival、category、role及每层所有块完全相同。全局1172、Long380、三Short各264无增删。
2. **真实warm混合。** 每张卡在[2000,4000)均有正Long计算及正Short计算；仅输入队列有两类、仅接纳过两类、仅两个窗口合起来混合，都不满足。另给每卡两类计算/active时间最小值、完整暖窗请求数，避免用极短边界片段掩盖几乎固定角色。
3. **32卡全active。** 每卡admission→completion区间与暖窗交集和=2000ms；计算加接纳后stall=active，窗口idle不能计stall。
4. **角色数量接近目标。** 报告时间加权平均、最小/最大Long数、K=20占时、K在18–22等邻域的占时；“20/12”必须注明理想设计还是实测。容许区间应预先声明，不能看结果后反向定门槛。
5. **名义容量。** 两策略各自全运行逐盘及逐链路扫描；保留失败结果，不按只满足平均容量或只满足暖窗容量放行。
6. **相位不是角色数。** 即使K一直20，新加入Long可能形成多个不同层相位。按Long计算/读释放时刻mod C统计集中程度、长期漂移、同时同相位的Long数，并把内部层与跨请求L0区分。不同卡的“第k个Long请求”不一定属于同一时间波，不能只按请求序号强行配对。
7. **顺序与性能证据。** 若只使用层日志，只能确认Short暴露等待、Long隐藏I/O及相位关联；某个Long是某Short的FIFO队头阻塞者仍需块级服务轨迹。不能把read lifetime画作SSD连续服务。
8. **人口与统计。** 暖接纳SLO分母会随顺序/策略改变，完整人口SLO另列；每种顺序/策略保留全部预定seed。这个模板已使用seed7 fixed时长校准，后续新seed应作为确认并披露选择过程，不能叫完全独立的无先验构造。
