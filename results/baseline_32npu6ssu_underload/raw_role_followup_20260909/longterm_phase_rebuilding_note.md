# 没有运行时屏障时，周期队列能否重新集中 Long 波

只读代码和旧结果的数学说明，不启动新仿真。本文件是 `longterm_role_math.md` 的补充；现有4个 pilot 的结果由主进程和审计代理处理。

## 同模板不是同步保证

把一个群组所有卡第k个逻辑层的计算起点记为 s[n,k]，下一层IO就绪为 R[n,k+1]。同画像层C相同时：

`s[n,k+1] = max(s[n,k] + C[k], R[n,k+1])`。

如果全部下一层读取都在各卡自己的计算截止前完成，群组跨度 `max(s)-min(s)` 保持不变。某些卡暴露等待以后，跨度可以扩大，也可以缩小；没有从“相同队列”推出收缩的定理。模型只在单张NPU的活动batch全部成员IO就绪后开算，不等待其他NPU，见 `continuous_batch_sim.py:2630–2648,3275–3298`。SSD完成之后还经过独立NPU接收链路，所有块收完才置层ready，见 `:4060–4109`。

因此最先应做的是消除已有的系统性漂移源：每个拟保持集中的群组使用同一完整画像模板、同一Long段层数、同一Short段次序和配额。原v8里不同卡有不同Short画像顺序、不同Long数量与额外尾部，不能用“完整队列重复”保持各卡后续相位。新输入的同模板虽然更有针对性，仍须检验真实收缩或扩张。

## Short→Long L0 是关键交接点

下一请求L0在前一请求最后一个计算层的开始时释放，并以这个最后层的结束为真实遮蔽截止；不是等前一请求完成才发，见 `continuous_batch_sim.py:3227–3265,3320–3326`。所以交接时应比较 Long L0 的 `io_start` 与 `io_ready`，同时记录前驱最后层 C；不能拿 Long 自己较大的 C 当这一层的已拥有预算。

每卡每次发1块，间隔0.1us（`continuous_prefill_client.py:22–23`），多个同时可发卡的次序被随机打乱，然后逐块提交（`continuous_batch_sim.py:3047–3094`）。按六个盘的提交state轮转，并不是把某一个Long完整层当作一个命令。1272块160K与1400块176K的无其他残留提交时，首末提交点分别相隔0.1271/0.1399ms；必要时还需计前一提交tick的残留。

当群组同刻释放时，块交织可能使各卡最后一批块在FIFO中处于相近位置。反过来，当Long L0释放跨度已经超过整层发块时间，较早卡可能在较晚卡开始之前就提交完整层，FIFO会保留这些先后次序（`sim.py:593–612`），不会自动把所有Long的就绪时刻拉成一个共同屏障。仅因为大家最终经过同一个盘，就宣称必然重新同步，是错误的。

“共同长波后的小Short读取把相位压窄”是一个可检验机制：若群组的Short读都被同一大段在前工作延迟，而这些Short的最后就绪时刻比其释放时刻更集中，下一层计算就可能收缩相位。这只是条件描述，完整层日志能测收缩，但不能单独识别某个具体Long就是所有Short的物理FIFO队头。

## 输入层面的后备思路

1. **保留现有同模板群组，改变分段长度。** 4L/12S与8L/24S的角色总人口相同；后者减少交接次数，使每次仍保持集中的Long段占更多时间。若每次交接都使跨度增长，单纯加长段只会延缓恢复，不能称为无限期稳定机制。
2. **将Short回到Long的预取留足真实计算预算。** 可在Short段末尾使用原始data中C较长、V较小的请求。比如32/64/80K、NQL2048的层C分别14.369103/25.106518/30.475233ms，层读量41.25/85.25/107.25MiB；80K2048仍比176K1024的C=31.416419ms略短，但有更长时间遮住下一Long L0。这改变了短画像构成，必须明确，不能当成原S32/1024不变的次序消融。所有这些新增画像逐盘V/C都低于原176K1024，在新`(block+npu)%6`条带下不会破坏原39.898850398GiB/s的任意组合名义证书。
3. **桥接只在其前后读取都及时完成时保持已有相位，不凭空重建相位。** 低V大C请求如果自己的首层又在前一短C预算内读不完，仍会引入不同的等待。需要逐条验证“前驱C≥实际下一层IO生命周期”的链条。给每卡插入长计算而声称有同步效果，或把新的计算量算作原输入调度改进，都不成立。

上述桥接画像只供现有pilot失败后的数学备选，本文件没有新增实验计划或运行它。若群组相位持续分散且无法通过合法输入自然收缩，现有约束下长期低U就不能由短窗实证推出。

## 每一轮应保留的可检验量

按群组、周期序号与逻辑层对齐，保存以下量；时间范围跨周期时同时报告全局Long数，避免只跟踪某20卡而忽略额外Long。

|位置或统计|记录量|可以检验什么|
|最后Short计算层|compute_start跨度、C及compute_end跨度|Long L0真正释放相位与隐藏预算|
|本轮首个Long L0|io_start/ready/compute_start各自跨度，暴露等待|交接使相位收缩还是扩张|
|Long段L1–L7|同逻辑层释放/计算跨度，模CL最小覆盖圆弧及最大空隙|避免把超过一个周期的绝对起点跨度误当相位分散|
|Long段全部层|最大IO生命周期、超过各自真实预算比例、暴露stall|长C是否持续遮住读；生命周期不等于盘busy|
|Short按画像|自身compute/active、暴露stall、读取/预算分位数|整机恢复是Short恢复还是画像/角色组成变化|
|整个周期与每2秒窗|实际Long/Short卡数的范围与时间均值、每卡正计算与切换次数|防止把配额纯C比例当成瞬时并发比例|
|整个运行|逐事件逐盘名义峰值及超限时间；每卡耗尽时刻|确认容量和有限人口尾部，不用idle制造低U|

同一周期需要跟随到其结束，主窗U仍按真实区间裁剪。周期尾跨统计窗时，不能混用“选层随访到ready”与“窗内暴露stall相加”两个口径。没有组级barrier的周期输入只是更长的有限批次；本次12秒若成立，也不构成无限时间稳态证明。
