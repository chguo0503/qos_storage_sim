# raw33 是充分子集，不是所有合法混合输入

本页仅做原始 `data` 的数学核验，**没有新增仿真，也没有低利用率实测结论**。采用 32 NPU、6×40 GiB/s、每块 176 KiB 的均匀条带；名义需求按当前已接纳请求每层 `V/C`，跨请求预取 L0 不额外计入该约束。下列原始行均整块对齐，没有外推、计算缩放或尾块 padding。精确数值及源文件 SHA 见 [JSON](raw_mixture_feasibility_note.json)。

## 为什么 33 行筛选并不完备

[独立筛选器](raw_data_random_5seeds/analyze_raw.py) 对每个画像 p 要求 `32 × ceil(blocks_p/6) × 176KiB / C_p < 40 GiB/s`。这样，无论 32 卡怎样同时选择这 33 个画像、条带起点怎样分布，每盘都有统一上界。它保证“任何组合都合法”，因此比证明“一个受约束的混合并发组合合法”更强；不满足单画像复制条件的 SS，仍可与低带宽 LL 共存。

## 一个含原始 SS 的具体并发证书

| 原始画像 | 类别 | 每层 C (ms) | 每层块数 | 最热盘块数上界 | 每盘 V/C 上界 (GiB/s) |
|---|---|---:|---:|---:|---:|
| 32K / NQL128 | SS | 1.178025959 | 255 | 43 | 6.126696251 |
| 192K / NQL4096 | LL | 135.967080956 | 1504 | 251 | 0.309850857 |

一个时刻若有 **5 卡 SS + 27 卡 LL**，任意条带起点下每盘上界为

`5×6.126696251 + 27×0.309850857 = 38.999454405 < 40 GiB/s`。

总需求为 **231.792845665 < 240 GiB/s**；每卡总需求分别 36.332733584 和 1.856636213 GiB/s，也低于 50 GiB/s 链路容量。若同时保留原“最近三短画像”32K/128、32K/256、32K/512，各 2 卡，再配 26 卡 192K/4096，则每盘上界 **31.344406659 GiB/s**、总需求 **186.475126058 GiB/s**。其中前两种是 SS，32K/512 在策略分类中是 SL。

这些首先是**并发状态的证书**，并不自动保证一条完整运行轨迹始终维持该组成。固定纯角色卡并持续维持数量上限可以把界推广到全程名义需求；这样又不满足“每张卡在暖窗内均有长短”的混合条件。轮换角色需要额外验证各时刻的数量约束，不能仅从本页推定。也未证明暖窗连续 2 秒全卡活跃。

## 为什么仍有排队损失的数学可能性

一个 192K/4096 Long 层在任一盘有 250 或 251 块，其盘内服务工作为 **1.049041748–1.053237915 ms**。27 个 Long 层若在同一盘共同形成一波先于短层的 FIFO 工作，合计约 **28.324127197–28.437423706 ms**，超过 SS 的 1.178025959 ms 计算隐藏时间，而 Long 自己的 C 为 135.967080956 ms。这解释了“名义速率低”与“某一波服务工作大”可以同时成立。

此处的先后关系是条件假设。实际发块会交织，提交和层间相位也会变化；没有事件轨迹就不能断言上述工作真的全部排在短 IO 前、会周期复发或能让设备 U 下降 10%。即使仅 5 张短卡损失严重，27 张长卡也会掩盖整机平均效果。上述服务工作不是从 read lifetime 推出的实测 SSD busy。

## 保持最近三短画像等条数时的容量权衡

三短 32K/128、32K/256、32K/512 各一条的每层 C 合计 **6.877638322 ms**、V 合计 **0.127731323 GiB**；按纯 C 加权的带宽为 **18.571974458 GiB/s**，不是三个 V/C 的算术平均。若各卡具有相同完整配额，按连续理想计算折算平均总工作量，短纯 C 份额 f 对应

`B_ideal = f×18.571974458 + (1−f)×B_Long`。

以每卡平均上限 240/32=7.5 GiB/s 代入：

| 低 B Long 原始画像 | B_Long (GiB/s) | 理想短纯 C 份额上限 | 每个短画像条数 / 每条 Long 的连续配额上限 |
|---|---:|---:|---:|
| 192K / NQL2048 | 3.748769473 | 25.306474% | 3.352563 |
| 192K / NQL4096 | 1.856636213 | 33.761589% | 10.076447 |

例如 Long=192K/4096，每卡短配额 9:9:9、Long=1 时，理想短 C 份额 **31.283191%**，总理想带宽 **226.743278689 GiB/s**；按本研究 32 卡原条带偏移 `npu//4` 精确累加，最热盘理想平均 **37.864064511 GiB/s**。10:10:10:1 时总理想带宽 **239.090164053**、最热盘理想平均 **39.927060532 GiB/s**。这些是**完整人口按纯 C 折算的平均工作量**，不能替代逐事件 current V/C 检查，也不能保证随机顺序下短画像不会同时聚集。

相反，原最近组的 Long=192K/1024，其 V/C 已为 **7.520933953 > 7.5 GiB/s**，三种短画像也全部高于 7.5；所以那四种画像下只要 32 卡都有当前请求，总 current V/C 必然超过 240。这说明该具体四画像组不满足约束，不能外推成原始 data 中不存在其他合法 SS+LL 混合。

本研究已测试的可行 raw 四画像没有复现低 U，所支持的结论仅限那些冻结输入；本页表明 raw33 筛选和已测四画像都没有穷尽原始 data 的受约束混合空间。
