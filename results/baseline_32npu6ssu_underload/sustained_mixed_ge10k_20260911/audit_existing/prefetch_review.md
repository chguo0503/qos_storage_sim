# 次级预取需求代理的独立口径核查

只读审查 `../audit_prefetch_demand.py`；未修改该脚本或运行仿真。

其分子是**实际下一层**在该盘的物理读量，分母是当前层原始计算预算 C。最后一层的目标换成下一请求 L0，替换当前名义量而非重复相加。内层与跨请求目标的 IO release 均断言等于当前 compute_start。两个变体分别在 `[compute_start,compute_end)` 和 `[compute_start,next_compute_start)` 保持该预算率。

在主审计已核对的连续单请求时间线上，同卡第二种区间的终点正好是下一层预算的起点，故不重叠；第一种是其子区间。同刻终止与开始事件成批处理，再评分下一正长度区间。这个结论依赖真实层顺序与时间戳已通过主审计。

初始请求 L0 没有前一层 C 预算，最后一个请求的末层没有后继，脚本明确排除二者。本批三个 Baseline 的每卡初始请求均在约 270 ms 内完成；Once 定序/随机的对应最大值为 278.030724 / 271.669735 ms，五格均早于 2 s。冻结输入每卡纯 C 至少 62.05 s，而单层 C 至多 31.416 ms，因此最后一层计算也不可能落入 `[2,60)`。这些是本批实际日志与冻结输入的边界检查，不能泛化到别的输入。

两个注意点必须保留：

- 延至暴露等待后的变体仍保持 `D_next/C_current`，没有将分母改成 `C+wait`。其时间积分可大于真实读量，不能叫实际 SSD 吞吐或实际传输字节数。
- 通过或未通过此代理均不等价于所有逐块 deadline 的可行或不可行证明；块的逐步提交、SSD→链路先后关系与具体非抢占服务顺序未由此单一代理证明。它与原来 current-request 名义容量判据独立，不用于剔除对照或改变原接受条件。

已完成 Baseline 的次级结果仅属于 **[2,60) 秒**：主定序两变体均峰值 39.676099 GiB/s、超 40 时长 0；主随机峰值 44.344865，超限分别 201.523121 / 209.890351 ms；备选 12L 峰值 40.627239，分别 8.465994 / 46.419555 ms。后两者不能据此称为真实 SSD 超载，且原名义全 run 检查均通过。可复算完整精度和源哈希在对应 `long_*_prefetch_demand.json`。

Once 定序峰值 40.167134 GiB/s，两个变体超限 6.938015 / 7.257232 ms；Once 随机峰值 44.438098，超限 125.688416 / 134.435211 ms。它们也保留在比较中：该次级检查依赖执行时间线，不是与调度策略无关的输入属性。五格均通过原接受条件，只有主定序 Baseline 在此新增次级检查中零超限。
