# 快短请求与桥接请求：已完成12秒试验的真实时序

这里仅说明 `bridge16_l176_6l_s64_s32q4k_stagger_ordered_seed7` 的已完成 Baseline 结果。它是4624条原始data请求构成的更长有限批次，全部arrival=0；本页只统计[2,12)s及其中局部，不能代替尚未完成的60秒试验。

## 每张卡如何排列

NPU0–15反复执行：**6条Long → 1条快短64K/1024 → 1条桥接32K/4096**。NPU16–31反复执行：**22条32K/1024 → 1条48K/1024 → 1条64K/1024 → 1条Long**；这16张卡在相同25项模板上取不同循环起点。每卡队列按自身真实完成进度推进，没有按钟表切换角色、同步屏障或额外空等。

|画像|总输入 / NQL|每层C(ms)|每层读取(MiB)|在设计中的作用|
|---|---:|---:|---:|---|
|Long|176K / 1024|31.416419|240.625|形成较大的读取波；其计算通常能遮住读取|
|快短|64K / 1024|12.625941|86.625|让前16卡实际处理计算更短的请求|
|桥接|32K / 4096|28.592842|38.5|读取量较少，最后一个计算层为下一Long L0提供较长预取预算|
|后16卡短请求|32K / 1024|7.257232|42.625|主要暴露等待的短画像|
|后16卡短请求|48K / 1024|9.941586|64.625|增加短画像种类|

桥接画像是原始data中的32K/4096行，**没有按每卡时间差插值、缩放C或额外插入虚拟计算**。它的C接近Long，不能与7–13ms的快短画像合并后声称所有Short都计算很短。这里short按相对Long的画像角色命名，实际模拟器分类均为SL，Long为LL。

## 同一绝对时间轴上的交接

[详细真实时序图：5160–5580ms](../figures/pilot/bridge16_handoff_real_time.png) 同时画NPU0与NPU25，没有移动、拼接任何区间。NPU0的具体请求为：

|请求ID|画像|计算区间(ms)|整请求暴露等待|
|---:|---|---|---:|
|22|64K/1024快短|5202.090814–5303.098340|0|
|23|32K/4096桥接|5303.098340–5531.841076|0|
|24|176K/1024 Long|5531.841076–5783.172429|0|

桥接最后层从 **5503.248234ms** 开始计算，同时预取下一Long的L0；读取在 **5519.230270ms** ready。该层读取生命周期 **15.982036ms** 小于前驱桥接预算 **28.592842ms**，距Long开算还有 **12.610806ms**。因此这一真实交接没有暴露等待，随后Long L1也随共同计算起点释放。不能直接删除桥接再沿用相同读取时间推算反事实，因为删除它会改变全系统相位。

同窗NPU25的32K/1024请求ID25000065，L1于 **5503.418328ms** 释放，预算截止 **5510.675559ms**，直到 **5519.984541ms** 才ready：生命周期 **16.566213ms**，暴露等待 **9.308982ms**。它是所画窗口内后16卡最大的、完整落窗的内部层等待；选择规则与原始记录都保存在JSON。这里没有把NPU0的Long指认为该Short的物理FIFO队头。

图中淡色“层读取生命周期”是从释放到全部块到达NPU的区间，包括排队及传输；它不等于SSD busy时间，也不意味着某个请求独占SSD。

## 相位与利用率分别验证

前16卡排除各自启动首个L0之后，共 **8176层** 的暴露等待之和为0；逐个同队列位置对齐，首层计算起点跨卡最大跨度始终为 **0.013527734375ms**。这是本输入维持长群组相位集中的实测证据，不是“相同模板必然同步”的一般结论。

在[2,12)s，前16卡快短64K/1024贡献 **8080.602087卡毫秒** 计算，占这16卡总时间 **5.050376%**；桥接贡献 **18299.418877卡毫秒**，占 **11.437137%**，两者均无暴露等待。后16卡总U为 **81.417108%**；其中32K/1024自身compute/active为 **77.441531%**，48K/1024为 **89.740504%**，64K/1024为 **92.948020%**。所以桥接仍与其他短卡的等待并存，不能用桥接较高U替代快短画像的结果。

当前输入使用新条带`SSU=(block+npu)%6`。每卡在其允许画像中对每盘V/C先取最大、再跨32卡求和，最热盘上界 **39.898850398GiB/s<40**；这覆盖任意当前角色组合。既定名义口径不额外计入下一请求L0，但模拟及详细图完整保留其实际读取。这一证书不是每层截止时刻都可行的证明。
