# 为什么代理的 92.8% 没有在正式仿真中保持

固定瓶颈盘块数后，差异不能再归因于普通 Ring Hash 的分盘方差。对正式 `fixedssu1_safe38_od_local` 的同一份 manifest，三盘连续服务代理仍得到 warm U=92.824%，正式仿真约 97.28%。原始时间、完整分析见 `proxy_native_gap.json`。

## 正式时间线显示相位逐渐散开

B 的每层计算是 93.6234367802 ms。把每个 B 层开始计算的时间对这个数取余，就能观察它们是否同时处在同一层计算周期。用圆周集中度 R 表示：接近 1 表示同步，接近 0 表示分散。

| 时间段 | 正式 B 层相位集中度 R |
|---|---:|
| 0–0.8 秒 | 0.999987 |
| 0.8–1.6 秒 | 0.995723 |
| 1.6–2.4 秒 | 0.827890 |
| 2.4–4 秒 | 0.168308 |
| 4–8 秒 | 0.296589 |
| 8–16 秒 | 0.078125 |

这不是单看平均 U 作出的猜测：B 层的启动时间确实从几乎相同变成散布在整个周期。

最先进入 A 块的 NPU 8，在代理中从 805.2497 ms 算 A，到 1553.8727 ms 开始下一 B；正式仿真是 805.1273 → 1543.3151 ms。首轮只提前约 10.56 ms，下一段 B 就带着这个提前量进入后面的层周期。第二组 A 块随后已经只用约 700 ms；后续 A 块更快。

这里的“A 块耗时”统一指：第一个 A 首层开始计算，到后一个 B 首层开始计算，包含跨请求的 B 首层读取等待。

| A 块开始时间 | A 块平均耗时 |
|---|---:|
| 0–1.6 秒 | 722.434 ms |
| 1.6–4 秒 | 603.593 ms |
| 4–8 秒 | 563.524 ms |
| 8–16 秒 | 542.208 ms |

35 个 A 本身纯计算只有约 530.87 ms。读取错开后，A 块逐渐接近这个数，NPU 利用率就提高了。

## 代理遗漏了一个会重复发生的离散调度效果

`sim.py` 的 `_static_qos_service_rates()` 返回的是**用于虚拟完成标签的名义服务率**。源码明确说它不表示并行传输；真实服务仍是一条条 176 KiB 命令。

路径短暂清空后，新 I/O 入队会执行：

```python
selected_path.virtual_finish = self._qos_virtual_floor()
```

因此，短读取结束、下一层再次提交时，这条路径可以重新从当前最小虚拟标签起步。连续代理只有实时带宽均分，没有虚拟标签状态，不能表达这个效果。

只读回放到 845 ms，观察了 805–843 ms 的真实命令与路径状态，确认 NPU 8 在每层重新入队时，标签反复向下重置，典型回退 0.000123–0.000134 虚拟秒，接近一个 `176 KiB / 1.25 GiB/s` 的虚拟步长。这里的“虚拟秒”是仲裁标签单位，不等于这次真实等待缩短了同样长的时间。

例如 A 的一个持续竞争层，代理用 28 块除以 1.25 GiB/s，给出 3.759766 ms。正式读取约 3.66 ms。按**每次待服务路径集合变化事件**精确积分该路径的名义 rate，在一些层的完整 SSD 读取期间只积分到约 27.21–27.30 块，但实际已经完成 28 块。有限突发中，实际服务量可以领先这个连续速率积分。

这个差异每层很小，却在 A 的许多层中反复发生。A 比连续代理更早结束，下一段 B 提前启动；B 的大读取逐渐错开，又反过来减少 A 的等待。最终差异被放大到数个百分点的利用率。

最初的一层还受到离散完成顺序影响：32 卡首次 B 的启动相位有约 0.25 ms 的分散，A 可以在别的路径尚未同时积压时借用更多带宽。这也是连续模型的完全同步假设没有保留的细节。

## 不是简单的提交时间或链路等待变长

- 客户端间隔是每命令 0.1 μs，A 一层 80 块的完整发送约 8 μs。
- 被观察的最后一个 176 KiB 命令在 NPU 链路上的尾部时间是 3.356934 μs。
- 两者均远小于每层约 0.1 ms 的实际提前；而且直接增加固定开销通常会使其更慢，不能单独解释这里为何更快。

但这些离散事件决定路径何时清空、何时重新进入仲裁。不能因为单个时间很短，就认为它对相位完全没有影响。

## 后续参数方向与限制

正式短试验可优先检查：A 块从 35 个改为 36 个；或 A 的计算时间增加约 2%–6%；或 B 的计算时间减少约 1%–2%。目的是补偿第一段 A 的提前，使后续 B 起算时间重新接近原来的 B 层相位，而不是改变调度策略。

这些只是方向，尚未证明有效。增加 A 块可能造成相邻两组 A 重叠，使逐盘需求超限；改变 B 计算也会提高其需求。需要同时检查整个运行区间的逐盘约束，以及 [4,8) 等后续窗口，不能把 4 秒截断试验当成长期结果。

当前证据说明：连续模型构造的低利用率状态对微小调度差异不稳健。原调度器含有短路径重新入队的有限突发优势，不能把配置的 CIR 或 `_static_qos_service_rates()` 返回值直接当成每层实测带宽。

所有回放只加了读取观察钩子，运行到 845 ms 停止；没有修改输入、调度策略或核心源码。`native_service_observation.json` 保存核心源码哈希、逐命令状态和每次 rate 变化，`native_service_integral.json` 保存独立积分结果。它们是机制审计，不是完整人口 SLO 实验。
