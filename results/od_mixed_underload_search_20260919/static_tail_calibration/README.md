# 离线冻结尾请求计算补偿：短试验

本目录尝试第三种合成请求 P。P 使用原 A 请求的完整读取数据和地址，只在每段 A 的最后一个请求增加少量计算时间。它是**改变请求画像**的实验，不是仅调整请求顺序，也不是 `data` 原始画像。运行时没有修改计算时间、暂停卡或控制 admission。

输入在运行前完整冻结。原始输入来自 `native_phase_lock_a102_od_local/manifest.json.gz`，原始完整时间线来自同目录 `result.json.gz`。最早进入 A 段的 NPU 8–15，在 A 段后开始计算 B 的时间，比共同的 B 层相位提前约 0.447–1.328 ms。

目标是让每个 A 段占据约 `8×C_B`，三个 B 请求占据 `24×C_B`，整个循环约 `32×C_B`。四组相差 `8×C_B`。最后一个 A 的末层已经预取下一 B 的首层，所以先用七层近似计算：

```text
P每层新增计算 = gain × 最早一组的相位提前量 / 7
```

按 `npu_id % 8` 映射最早那组的补偿值，并在每轮重复同一值。两次短试验分别取 gain=0.5 和 1。普通 A 每层计算 1.9338804869770942 ms；gain=1 的 P 为 1.997729–2.123614 ms。每张卡有六个 P，总计192个。B保持93.62343678022687 ms。所有C都已写入 manifest 后才启动仿真。

每次使用原模拟器运行到8秒后截断，检查 [2,4)、[4,8) 的利用率与逐盘需求，以及 [0,8) 全区间逐盘需求。保存截止时刻的层时间线。**没有完整排空，不报告 TTFT SLO，也不把8秒短试验当作长期结论。**

P 会增加计算时间，也可能延长 A 角色驻留，导致原来不同组的 A 重叠。即使 P 自己的 V/C 下降，也必须重新检查所有卡的逐盘总需求。对每卡混合的检查同时保留普通 A 和 B，不能靠仅执行 P 冒充原有短请求。

- `experiment.py`：冻结和回放入口；没有核心仿真修改。
- `inputs/`：含每请求实际 C 的冻结输入。继承的base画像描述仅供来源追踪；实际计算按请求的 `per_layer_us` 和 `calibration` 中的明确记录为准。
- `runs/*/command.json`：完整补偿公式、源trace及输入哈希、逐窗结果、核心源码未变检查。
- `runs/*/live_summary.json.gz`：8秒截断时的原始层时间线。

第三次短试验从 gain=0.5 的冻结输入出发，仅增加 NPU 24–31 的 P 请求计算时间：`额外每层计算 = 0.3 × 该卡首轮下一 B 提前量 / 7`。所有值仍在重放前冻结，见 `refine_last.py`。三次均完成，结论见 [RESULTS.md](RESULTS.md)：只改善短期相位对齐，未保持 4–8 秒低利用率。

本实验校准的是原策略的一条已知时间线，因此即使成功，也只能作为对抗性合成输入的例子，不能外推到普通随机请求或跨种子的泛化效果。
