# 同一短请求的完整层周期放大

采用正式完成的OD结果，NPU 19、请求 19000031，2.123278920–2.137499730秒；原始L0到L4的4个连续周期，均不跨请求。合成画像和对抗性地址选择，不是原始data样本。

A每层V=13.750000 MiB，C=1.895961262 ms，B=V/C=7.082283086 GiB/s。I由数据到齐时刻减去上一层计算结束得到，逐周期与原始io_barrier_wait匹配。

4周期该卡U=53.329206%，整机warm U=97.281098%。这里V、C均恒定、没有额外计算排队；b按完整周期平均，b/B=C/(C+I)。这不是瞬时公式，不适用于把跨请求读取直接除以当前请求需求。

局部逐盘名义需求峰值为 [35.27891662604395, 37.858637158208104, 35.84876875353455] GiB/s；全warm逐盘峰值为 [36.146702786846696, 37.858637158208104, 36.94901315529047] GiB/s，均低于40。名义需求仍按当前请求V/C统计，跨请求预取不额外叠加。

并发B例子：NPU0、请求2，本层计算 [2.115851192, 2.209474629) 秒，C=93.623436780ms。下一层读取207.968750MiB，IO提交2.115851192秒，数据到齐2.166344182秒，IO在途50.492989868ms。

IO在途包含排队、SSD服务与传输，不能画作全程SSD服务。源结果没有层级SSD最后完成时刻，图中明确不提供虚构服务条，也不把io_ready标成SSD完成。并发B只说明重叠，不能单独识别哪张盘或哪条Path的因果贡献。

图解释的是：总的平均速率约束成立，仍不保证每次预取在各自计算预算内完成。此局部例子不证明整机利用率已降至80几，也不证明长期保持同样程度的退化。
