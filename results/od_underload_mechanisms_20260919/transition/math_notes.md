# OD 欠载退化：数学候选与不能混淆的边界

本页是构造与待检验预测，实测以各 `pilots/`、`runs/` 的记录为准。不会把 CIR 当成实际带宽硬上限。

## 1. ASU 和 OD 的差别

ASU 把不同 NPU 的命令放进同一条 FIFO 路径。一个 NPU 先发入的大批读取，可以挡住其他 NPU 后来的短读取。OD 为每张 NPU 保留独占路径，消除了这种跨 NPU 的同路径队首等待，但所有路径仍争同一块物理盘。

32 卡、每盘 40 GiB/s 时，OD 每路径 CIR 是 1.25 GiB/s。它是保证份额；PIR 无限，空闲份额仍可借。原生算法按组与路径两级仲裁，实际命令逐个非抢占执行，并不是每条路径实时同时传 1.25 GiB/s。组内活跃路径数不同时，借用后的实际份额也不一定相等。

新 8192 槽约束与上述带宽规则独立：每卡每盘 256 个未完成 SSD 命令，占用至 SSD 完成；空闲卡不能借槽。盘完成后的补发没有额外反馈延迟，仍遵守原每命令 0.1 μs 节拍。因此不能仅从“队列有限”推断吞吐下降。很可能只是等待由盘内移到 host，层周期完全不变。

## 2. 原先双画像同层竞争模型本身很难给出长期 80 多

用 q=40/32，令 A 每卡每盘需求为 a=alpha*q，B 为 b=beta*q，其中 alpha>1、0<beta<1。x 是正在执行 A 的卡的比例。假设固定角色、B 的大读取同步、C_B 远大于 C_A，忽略有限层、请求切换和分盘差异。

旧连续近似模型的整机损失为：

```text
loss ≈ x * beta * (1 - 1/alpha)
欠载要求 x*alpha + (1-x)*beta <= 1
所以 loss <= beta*(1-beta)*(alpha-1) / [alpha*(alpha-beta)]
```

对 alpha 求最大值时 `alpha = 1 + sqrt(1-beta)`。再令 `s=sqrt(1-beta)`，损失变成 `s^2*(1-s)/(1+s)`；最大值在 `s=(sqrt(5)-1)/2`，约 **9.017%**，对应 U 约 **90.983%**。

**这是这个简化双画像模型的边界，不是所有 OD 负载的定理。** 有限层、多个时间尺度、首层预取、多盘 barrier、离散调度和借用规则均不包含在推导里。它说明：沿着同一个过简化模型反复调两类参数，本来就不该期待轻易预测出 80 多的整机 U。

旧实测还比该近似更快恢复：`od_mixed_underload_search_20260919/native_phase_lock_comparison.md` 中较强候选 OD `[2,4)` 为 94.05799%，`[4,8)` 98.28915%，`[8,12)` 99.37819%。原逐块虚拟标签重入会改变后续相位，不能把短窗低值当长期稳态。

## 3. 本次改试 A→B 的首层预取预算错配

各卡静态重复 `(AB)^16`，每请求 8 层。A 的最后一层计算期间预取 B 的首层。

隐藏 A 自己下一层，需要看 `V_A/C_A`；但 A 切到 B 时，要比较的是 **V_B/C_A**。分子已经换成 B，预算仍是 A 最后一层的短计算。仅检查当前请求的 `V_current/C_current` 没有覆盖这项期限。

理想均衡三盘、32 卡完全同步且 OD 公平服务时，设 B 的同步首层读取时间 `T_B = rho*C_B`，则每一 AB 循环：

```text
纯计算时间 = 8*(C_A+C_B)
A→B暴露等待 ≈ max(0, rho*C_B-C_A)
U ≈ 8*(C_A+C_B) / [8*(C_A+C_B) + max(0,rho*C_B-C_A)]
```

令 r=C_A/C_B，U<90% 的条件为：

```text
rho > 8/9 + (17/9)*r
```

rho 接近 1 且 r 很小时，这个理想构造可以接近 `8/9=88.89%`。例如 r=.01、rho=.99，U≈89.183%。如果各画像自身每盘需求都相同为 `0.99*1.25`，任何时刻当前画像总需求都是 39.6 GiB/s，仍会在短→长边界等待。

这证明的是**简化同步模型中，当前画像需求欠载不排除低 U**。真实普通 Ring Hash 的不同盘计数和层相位可能破坏同步，必须做长时间仿真；下面原生候选只是检验它，尚不保证成立。

还必须承认：这种等待不一定是 OD 独有。以释放时刻 r_j、必须读完时刻 d_j、读取字节 V_j,d 表示 I/O 任务，任何调度器要完全隐藏 I/O，都至少要求：

```text
对每块盘、任意时间段[a,b]：
所有满足 r_j>=a 且 d_j<=b 的任务，其V_j,d之和 <= 40*(b-a)
```

时间用秒、V 用 GiB。32 张卡同时在 A 最后一层发出 B 首层时，这个真实的期限需求很可能超限。Once 也不能创造额外物理容量；若 Once 同样低，只能说明共同的预取时机限制，不能宣称 OD 公平分配独有的弱点。

## 4. 两个普通 Ring Hash 候选

所有读取命令均精确 176 KiB，总输入至少 10K；rid=`npu*1000000+queuepos`，每层复用原 Ring Hash。不筛选地址，不复用 ID，不错峰到达，不加运行时 barrier。

|候选|A 总长 / miss|A 层 C|A 层块数|B 总长 / miss|B 层 C|B 层块数|
|---|---|---:|---:|---|---:|---:|
|a1024|10K / 1024|3.566243619 ms|72|200K / 2048|75.25 ms|1584|
|a512|10K / 512|1.856638860 ms|76|200K / 2048|75.25 ms|1584|

A 的 C 沿用 data 的同 miss、32K/48K 线性长度外推，权重 2.375/−1.375。B 的原 data C=70.740537841 ms，显式缩放到 75.25 ms，以给热点盘留容量余量。因此两者是**构造/外推计算时间**，不是原 data 的实测行。

a1024 的 16 轮每轮全 A 同步参考峰值 39.81733 GiB/s。B 在 C=75 ms 时全 B 同步峰值40.04822，改成75.25 ms后降到约39.915 GiB/s。B 首层最忙盘总量/40 的均值为73.841524 ms，理想同步 U 约89.97%。

然而，a1024 任意画像与请求组合的静态包络仍约47.5 GiB/s，**全 A 与全 B 各自欠载，不能推出 A/B 混合时也欠载**。必须按真实 admission/completion 逐事件重算每盘需求。a512 则主动允许短 A 阶段局部过载，更不能写成严格欠载。

## 5. 实验判据

- 4 秒 pilot 不提供 SLO；暖窗仅初筛。
- 若 warm U<92%，同输入完整排空 `(AB)^16`，核对 `[2,4)` 和 `[4,8)`；两者每卡都须真实计算 A/B，且持续活跃。
- 若后窗仍低，再扩至 `(AB)^100`，核对 `[8,12)`、`[12,20)`、`[20,40)`、`[40,60)`，不把排空尾部当长期退化。
- 分别报告精确每盘需求峰值、过载时间比例、同层等待、跨请求 L0 等待；给 Once 对照。
- 当前画像 V/C 不另加下一请求 L0，但跨请求等待及所有读取都完整保留。报告这项口径，不能把名义欠载说成所有实际 deadline 需求都欠载。

## 6. 实测后的结论

原生完整对照已结束，见 [README.md](README.md)、`comparison.csv`、`comparison.json`。a1024 的 OD U 从 `[2,4)` 91.002% 恢复到 `[4,8)` 94.840%、`[8,10)` 98.446%；Once 对应 98.160%、98.681%、98.918%。所有这些中间窗口每卡都混合运行 A/B，没有排空。两策略所有请求 admission SLO×1.5 都达标。

这次支持“短→长首层预取预算错配会造成早期利用率下降”，但没有支持“这一固定队列能保持长期低利用率”。也没有实现严格全程欠载：OD warm 有 0.03797% 时间第二块盘轻超 40 GiB/s。有限全输入的 91.888% 不能当成长时稳态。没有继续扩大输入或加入运行时同步来伪装稳定结论。
