# 为什么改为每轮离线选择真实整数 miss

这是一个按 OD 量身构造输入的机制实验。它不代表随机请求普遍如此，也不证明严格欠载下会长期低。50 轮的最终指标必须来自 `formal/` 中无规划 hook 的原 API 重放；`planning/` 中的输出只用于生成输入和检查因果关系。

## 把“等其他卡”换成事先选定的计算请求

每卡重复三条请求：A、普通 B、尾部 B。A 是大读取、短计算，普通 B 是类似读取量、长计算。A 同时集中出现时会造成逐盘强突发过载，之后 B 的长计算阶段则提供较宽的预取时间。

我们希望尾部 B 在每轮共同的时间附近算完，使下一轮 A 重新聚集。共同时间在规划前固定：第 1 轮 1650 ms，第 2 轮 3300 ms，依次增加。它不是运行时提交给盘或 NPU 的 deadline，更不是阻止 NPU 继续运行的 barrier。

如果尾部 B 的第 0 层在 `s` 开始，后面没有 I/O stall，8 层需要的每层计算时间是：

```text
目标 C = (这轮共同结束时间 E - 这张卡的 B0 起算时间 s) / 8
```

早起算的卡选择稍多的新 token，晚起算的卡选择稍少的新 token。每张卡实际执行相应的计算，没有额外 idle。不是所有调整都增加计算；相对于原 B，某些首轮请求会减少 miss 和计算时间，必须同时统计有符号变化、增加量、减少量和绝对变化。

## C 不能随意捏造：保持命中量，改变整数 miss 和总长

普通 B 选 128K 总长、miss=3328。这里 K=1024，因此命中 token 数是：

```text
hit = 128*1024 - 3328 = 127744 tokens
读取块数 = hit/128 = 998
每层读取量 = 998*176 KiB = 171.53125 MiB
```

尾部 B 仍保持 hit=127744，选择整数 miss `m`，总输入改成 `127744+m`。这样计算工作量改变，KV 读取量不改变。每条请求用自己唯一的物理身份做原生 Ring Hash，没有复用前缀、筛选地址或改变放置算法。

计算时间从原始 `data` 表内插：miss 取 2048～4096，长度使用相邻的 96K/128K 或 128K/160K 行，四个角的权重都在 0～1 且总和为 1。没有外推。内插不是一次新的实机测量；这里保证的是与该数据模型内部一致。

扫描这 2049 个整数 miss，选计算时间最接近目标 C 的一个。可达 C 为约 46.162～93.521 ms。相邻整数 miss 的最大 C 差约 0.023452 ms，所以最近整数选择产生的每卡 8 层结束误差不超过：

```text
8 * 0.023452 / 2 ≈ 0.093808 ms
```

两张卡间结束时间差最多约 0.187616 ms，而不是 0.093808 ms；后者是单卡相对于 E 的误差界。只要 B 内部读取持续隐藏，这个误差每轮都围绕当轮 E，而不是一轮一轮累加。

## 规划可以观察 s，正式实验不能再调整

输入生成阶段使用一次单独的规划仿真，在尾部 B 的 L0 真正开始前观察 s，计算整数 miss，记入输入。规划时只更新该请求运行态的计算参数和对应负载副本，原始输入对象、放置、队列顺序、调度器源码均不改变。

随后冻结所有请求，包括每一轮、每一张卡的 miss、总长、C 和唯一 Ring Hash 放置。正式运行另开进程，只加载这个 manifest、调用原 API，没有任何规划 hook，也不会再观察 s 来改 miss。

这在 OD 中有具体的因果依据：在请求首次计算开始前，OD 的固定路径、固定 CIR、FIFO 命令服务都不读取其未来 C；读取量和放置也没变。正式输入虽然更早给出 C，但它只在相同的首次计算事件上起作用。最有力的检验仍是逐请求、逐层原始时序和规划完全一致，而不是只看利用率相近。

两个周期、唯一物理身份的小验证已经做到：全部 request/microbatch/layer 指标逐字段相等，六类层时间误差为 0。B 内部 I/O stall 全为 0，下一 A0 提前就绪；实际结束 spread 为 0.17261、0.17533 ms，符合量化界。仅两周期到 3.3 秒，不能据此报完整 warm [2,4) 或长期结论。

## 为什么前一版固定 C 失败，这版还值得验证

固定每卡一个 C，只能消掉某一轮的相位差。后来 Ring Hash 分盘、离散服务、轮转状态和请求节奏改变，原补偿值就不再适用，已有 12 轮实验确实恢复到了高利用率。

现在每轮使用事先冻结的不同 miss，补偿的是那一轮规划出的差值，因此数学上有机会反复收拢相位。但这是用大量离线信息设计的输入，仍有强烈选择偏差。正式 Once 使用同一份输入；这些 miss 是按 OD 的轨迹选的，并没有按 Once 的轨迹重新选择。

两策略的请求清单相同，不代表每一时刻正在运行的请求组合相同。Once 若更早打散聚集，需求曲线自然会不同。再加上两策略的路径数量、静态 CIR 类池、OD 独有槽位限制不同，最终差值是完整配置对比，不是纯选路因果消融。

## 长期统计的必要限制

正式输入共 50 轮，每卡的纯计算总量须大于 60 秒，队列入口有硬校验。这保证 [20,40)、[40,60) 不会因为某些卡已排空而降低利用率。仍需检查这些窗口所有卡活跃、每卡确实计算过 A/B，并报告真实逐盘需求是否过载。

本构造的 A 阶段可能达到每盘约 300 GiB/s 的名义需求，远高于 40 GiB/s。它属于局部强突发过载，不是持续欠载。不能用“总读取量/总纯计算时间小于总容量”来替代逐时逐盘的欠载检查。
