# 同一冻结输入的提交种子敏感性检查

只把 OD 的 `submit_order_seed` 从 7 改为 19。50 周期输入文件逐字节相同，32 NPU、3 SSU、每盘 40 GiB/s、8 层，以及每盘 8192／每卡每盘 256 队列槽均保持不变。正式运行没有加载规划模块或安装额外观察钩子，也没有要求 seed19 满足 seed7 的目标时刻。

|窗口|seed7 NPU 利用率|seed19 NPU 利用率|两者 SLO×1.5|
|---|---:|---:|---:|
|20–40 秒|79.321675%|79.321675%|800/1184 = 67.567568%|
|40–60 秒|80.175183%|80.175183%|768/1152 = 66.666667%|
|20–60 秒|79.748429%|79.748429%|1568/2336 = 67.123288%|

三个窗口均为 32 卡持续活跃，且每卡实际计算过 A、B。首次卡排空为 82.499927 秒，以上窗口没有尾部空闲。SLO 使用窗口内接纳的请求，并跟踪至完成；分母是冻结输入中每个请求的 `8 × 每层 C`。

独立重算通过：每个 seed 完成 4800 请求、38400 层、38630400 个块；两者全部请求记录和微批次／层记录完全相同，六项关键层时刻的最大差均为 **0 ms**。输入和核心源码哈希已核对，seed19 运行前后均未改变。

50 个周期的末端卡间跨度为 0.145971–0.185729 ms；首周期 0.172613 ms，末周期 0.166311 ms，未出现逐周期扩大的相位误差。前十周期平均跨度 0.175977 ms，后十周期 0.177216 ms。末周期已经涉及排空，只用于比较最终完成时刻；长期利用率结论使用前述无排空窗口。

**这个检查的结论很有限。** 种子只改变同一时刻客户端 ready-NPU 列表的处理顺序。OD 各卡使用不同 Path；同刻客户端提交发生在 SSD 调度之前，而 SSD 同优先级仲裁按 Path／轮转位置选择。这与本次全部服务时序不变的结果一致：这个种子变化没有给 OD 制造有效的时序扰动。因此不能把结果描述为已经证明对计算延迟、SSD 服务噪声或普通随机输入具有鲁棒性，更不能当成另一个独立随机工作负载样本。
