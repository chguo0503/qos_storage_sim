# 固定计算相位补偿：单轮成立，长期保持失败

这是额外的合成机制验证，不代替原始 `data` 的长期实验。两次固定输入校准均未保持稳定低利用率；第二次只是延缓恢复。**不能把前几秒约 79% 写成已经找到长期 80 多的案例。**

## 怎么构造输入

32 NPU、3 SSU，每盘 40 GiB/s，8 层，所有请求在 0 时刻到达，每卡依次执行 `(A,B,B)^12`。每个请求总输入都是 128K；A 的 miss=256、原始每层计算 6.024011549 ms；B 的 miss=4096、原始每层计算 93.017325202 ms。每层 A 读取 1022 个 176 KiB 块，B 读取 992 个，分别为 175.65625 MiB 和 170.5 MiB。A/B 是“短计算/长计算”，并不是“小读取/大读取”。

OD 的每盘 8192 槽固定分成每卡 256 槽，满额暂停对应卡向对应盘下发；盘带宽仍可借用，CIR 不是 PIR 硬上限。Once 保持原配置，未启用 OD 专属槽位限制。本对照不是同限深的纯路由消融。

每卡的三个位置各有一个物理 KV 前缀，后续每轮重复读取它。共有 96 个物理前缀，各卡之间不同；所有逻辑请求 ID 唯一。布局逐块由原生 Ring Hash 生成，没有筛选地址或改变放置算法。**重复固定前缀不同于每次随机产生新前缀，必须作为输入构造披露。**

每轮最后一个 B 的计算时间允许预先调整。若尾部 B 的首层起算为 `s_i`、原计算为 `C_i`，且内部 I/O 都已隐藏，结束时刻是 `e_i=s_i+8*C_i`。取 `E=max(e_i)`，然后冻结：

```text
新的每层 C_i = 原 C_i + (E-e_i)/8
```

这是给较早的卡增加计算量，运行中不会查询时序再补齐，也没有插入 idle 或 barrier。**调整后的尾部 B 是显式合成计算画像，不再是原 data 的精确行。**

## 两次校准结果

先运行原始 ABB×2。首轮尾 B 起算差为 57.290268 ms，小于单层 C=93.017325 ms；B 内部 I/O 均隐藏，下一轮 A0 也已经提前就绪。满足本次校准的因果充分条件：改变尾 B 的 C 前后，其首层起算不变。

第一版每卡固定一个尾 B 的 C，范围 93.017325～100.178609 ms；每轮总计算增加 1.807%。实际首轮结束差精确变为 0，但下一轮出现 6.944656 ms 偏差；末三轮差值达到 1435.692、1521.801、1583.251 ms，仍逐渐失锁。

两次完整运行读取同一个 manifest，均完成 1152 个请求、9,234,432 个 I/O 命令。以下窗口两种策略都尚未排空，32 卡全部持续活跃且各卡实际混合 A/B。

[2,18) 汇总有明显差距，但 OD 仍持续恢复；不能把该 16 秒的平均值宣称为长期稳定值。每窗 SLO 人口是该窗口内 admission 的请求，两个策略的人口数量不同，精确数量保留在 CSV。完整相同的 1152 个请求中，OD/Once 的 SLO×1.5 为 **71.962% / 90.972%**。

OD/Once 完整 makespan 为 22.287246 / 20.119420 秒，全输入 U 为 84.419% / 93.515%。这些全输入值包括冷启动和排空。Once 首张卡在 19.095770 秒排空，因此其 [12,20) 的 94.346% 混入尾部，不能与上面的全活跃窗口等同。

最大逐盘名义需求达到 314.684 GiB/s。这是短时间的强突发过载，并非始终贴近 40 GiB/s 的轻微超载。两策略均使用真实逐事件活跃画像求需求，详细过载持续比例见 `comparison.csv/json`。

OD 限深 256/卡/盘，Once 为原配置无限深度，且 Once 还使用自己的静态 QoS 类别池。**这是一组完整策略效果差异，不能据此把收益唯一归因为选路，也没有排除队深差异的影响。** 因为相位保持已经失败，本分支没有继续补 None 队深消融或扩大输入来宣称成功。

## 能确定什么，不能确定什么

单轮补偿公式是成立的：两次校准目标轮的 B0 起算最大变化均为 0，尾 B 完成差也均精确为 0。

失锁不是因为 B 的内部层读不完：第二版全部 12 轮，所有 B 内部层 I/O stall 都是 0；每轮下一 A0 都已提前就绪，最小裕量 51.627073 ms。

但“计算同时开始”不等于调度器完整状态重复。代码仍保留原生 RR 游标、连续推进的客户端 RNG，以及其他事件状态。第三轮 0.180435 ms 恰好等于 43 个 176 KiB 命令在 40 GiB/s 下的服务时间，随后偏差扩大。当前输出没有逐周期完整内部状态，**不能唯一归因于 shuffle、游标或某一个具体细节**。

没有第三次参数搜索、运行时修正、强制等待或修改核心来维持效果。该分支按事先约定的两次校准上限停止，不扩大到 40 轮。

## 文件与验证

- `math_design.md`：因果充分条件、真实画像限制、长期平均的数学口径。
- `inputs/*.json.gz`：完整冻结输入；`cal2_construction.json` 清楚列出两组固定 C。
- `runs/*/result.json.gz`：原始请求与层时序；`analysis.json`、`brief.json`：逐轮相位和窗口指标。
- `run_calibrated.py`：调用原 API 完整排空，没有 observer 或时序 hook。
- `audit_fixed_input.py`、`independent_audit.json`：逐块核对 native Ring Hash、逻辑 ID、前缀复用、冻结 C、真实计算时长、命令守恒和限深。
- `build_comparison.py`：只读已完成原始结果生成 Once/OD 的 `comparison.csv/json`。比较窗口同时保留 all32active；Once 的较早排空已在上文明确。
