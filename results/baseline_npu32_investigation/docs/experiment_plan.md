# Baseline 32 NPU 调查：实验设计

开始：2026-09-07 00:50 JST；用户上限六小时。已有模拟器和策略保持不变，新增脚本和结果单独保存。

## 待检验的问题

1. 原32卡平均利用率高，是否源于长计算请求的时间权重，而非短请求不再堵塞？对原始全部请求按画像重新核算计算占比、接纳SLO和I/O等待。
2. NPU数量本身能否解决旧4卡坏例？先保持每组4卡/1盘的物理关系，复制成32卡/8盘；再改变同一输入的分盘方式。
3. 在每盘名义需求都小于40 GiB/s时，能否构造32卡多数卡都被阻塞的输入？增加低带宽、短计算受害者的比例，并保留大读取背景流。
4. 同样坏输入上，原生Once、5 ms Once/New once、S1–S3以及multi-SSU deadline策略是否改善？同时保留失败和指标之间的取舍。
5. 这些现象是否依赖1K外推画像？增加完全取自项目data格点的固定画像和可变画像对照。

## 科学口径

- SSD 40 GiB/s；每NPU独立50 GiB/s接收链路；每请求8层，batch=1。
- 同组策略使用完全相同的请求、到达、物理placement与submit seed；保存manifest及源哈希。
- exact旧输入保留不足176 KiB的尾块。当前5 ms适配器只支持完整176 KiB IO，因此该轨单独使用显式补齐输入；必须核算补齐带来的字节差异，并用原生策略做桥接对照。不得暗改旧实验。
- 主窗口固定[1000,2000] ms；额外报告[2000,3000] ms及全程。每卡理想计算工作量足够覆盖窗口，并检查真实active/stall/idle恒等式。重分卡可能使部分卡提前排空，不能将idle称为I/O stall。
- 有限输入保存全部完成请求；接纳到完成与到达到完成分别报告，不把入口排队藏进指标定义。
- 固定饱和画像的名义需求为 `d_s = sum_i V_is / C_i`（换成GiB/s）。可变输入按每卡完整读量/完整纯计算时间加权；它是给定配比的必要资源检查，不是任意一秒利用率的硬上界。
- 冻结策略参数沿用coflow正式结果：pipeline选卡、1.0 ms信用窗口、urgent_short。fixed选卡仅作明确标识的消融。
- 种子42用于构造与初筛；代表输入冻结后用7、123检查，不能按每个测试种子重新挑最好策略。构造实验不声称代表生产到达分布。

## 解释中需避免的错误

- Path0在每个SSU各有自己的队列，不是所有盘合并一条物理队列。
- 一个大层由许多可交错的176 KiB命令组成，并非整个大层是一个不可抢占命令。应以实际前方FIFO命令与末块完成解释阻塞。
- `sum(V/C) < bandwidth`只约束长期平均；有限预取窗口能否赶上，还受排队、跨盘最后分量及接收链路影响。
- 自然错相不等于短deadline都能满足，原相位探针已提供反例。
- 当全部输入都是高V/C短请求时，物理带宽过载必须单列；不能期待调度消除缺失的容量。

## 外部研究定位

Varys将一组流必须全部完成的应用约束建模为coflow，并联合考虑源端与目的端资源；这支持同时检查SSD与NPU接收链路的分析方式。它讨论的网络模型和目标不等同本项目，不能把其算法保证直接套到这里。

来源：[Chowdhury, Zhong, Stoica, Efficient Coflow Scheduling with Varys, SIGCOMM 2014](https://mosharaf.com/wp-content/uploads/varys-sigcomm14.pdf)。本次性能结论以仓库原始结果和新仿真为准。

## 根据用户要求补充：每卡多种不同短流

用户指出固定画像不断重复不切合实际，要求检验多种不同短请求。2026-09-07 02:00 JST 左右，在新增仿真结果出现之前冻结如下扩展；原固定流只保留为机制控制。

每张NPU都含三种短画像和一至两种长画像，各卡完整配额相同；先按整数配额提供至少 `4000 ms + 两个最长请求的纯计算时间`，再独立打乱整份请求列表。没有重复固定小deck，各卡不同随机序列。使用seed7、123；所有C不缩放，所有I/O精确176KiB，32卡/8盘条带，固定每四张原NPU的条带偏移。

- 外推短画像 `1K/NQL128、256、384` 加原始 `192K/NQL256`，两种配额使短请求计算占比约72%、80%。
- 原始短画像 `32K/NQL128、256、512` 加原始 `192K/NQL1024、2048`，三种配额使短请求计算占比约33%、38%、58%。
- 额外原始短画像 `32K/NQL128、48K/NQL256、64K/NQL512` 加上述两种长画像，短计算占比约38%；同时改变短流数据体积和计算预算。

共六种配额、两个种子、Baseline/Once/New once三策略，即36作业。每个输入的三策略固定分卡、5ms collector且在同一台机器上运行。逐manifest核对实际盘/链路容量、画像覆盖、完整请求人口与每卡不同序列；逐结果核对主/第二公共窗口均有工作。

候选中平均过载或完整配额导致明显更长运行的配置保留描述而不并入已选36作业；选择依据是输入容量和运行成本，未按策略结果挑选。完全取自data的结果与含1K外推的结果单独汇报。对每种短画像重算同一request_id群体的接纳后计算占比、stall和SLO，不能仅看整机U。


## 结果出来后的有限复核扩展

以下为研究过程中提出的复核，不声称属于最初预注册计划；每一补充在运行各自策略前先冻结输入，原36作业和原策略参数不变。

- **混合输入的其他策略，8作业**：E72与V38种子7，各补S1/S2/S3 pipeline和S3 fixed；同一输入的Baseline/Once/New once已经在36作业中，不重复计数。目的为检查固定重复流上的选卡失败是否推广，逐画像保留收益和代价。
- **六盘混合，4作业**：A直接保持八盘E80种子7的请求人口、顺序和全部非placement字段；B以原data多体积画像重新配额，保持最热盘平均需求低于容量。各对照Baseline/New once，同一台机器运行。目的为检查用户原32/6拓扑下的混合流，只有A是同人口拓扑对照。
- **严格三SS，6作业**：原data的32K/NQL128、48K/NQL256、64K/NQL128，加192K/NQL1024、2048，种子7/123各Baseline/Once/New once。原V38的64K/NQL512在模拟器中实际属SL；这次使用三种真正SS检验同类别内部是否仍有差异。画像及配额一并改变，不能单独归因类别标签。
- **仅三种不同低带宽短画像，3作业**：1K/NQL128、256、384，各Baseline/Once/New once。该输入平均负载仅14.22%，是独立控制，不能称为从E72同人口同负载中仅删除长流。

各输入参数、完整列表、随机种子与策略分别保存在对应mixed_policy、mixed_six_ssu、mixed_strict_ss、mixed_controls目录。未根据策略结果重新优化配额、窗口或策略参数。后续全部原定与新增配对完成后统一复算和汇报；不删除变差策略或画像。
