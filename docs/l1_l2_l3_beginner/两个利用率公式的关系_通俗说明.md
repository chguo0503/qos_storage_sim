# 两个利用率公式的关系：一个看“现在”，一个估计“平均”

本文只用纯文本公式，不需要数学公式渲染。下面的小数字都是教学假设，没有新增仿真实验。

**最需要先澄清的是：这两个公式回答的问题不同。它们在同一个时刻不相等，并不一定是谁算错了。**

| 名字 | 它在回答什么？ |
|---|---|
| `U_actual(t)`：真实瞬时利用率 | 在时刻 t，到底有多少张卡正在计算？ |
| `U_est(t)`：带宽模型的估计 | 假设时刻 t 的请求画像和可用带宽保持不变，理想流水稳定后，平均能有多大比例的时间用于计算？ |

我之前使用 `U_est(t)` 这个名字，容易让人以为它能预测“这一瞬间有多少张卡在计算”。更准确的理解是：**拿这一刻的条件，估计持续运行后的平均水平。**

**1. 先只看一张卡，它只能“正在计算”或者“没有计算”。**

对于一张卡：

```text
正在计算：U_actual(t) = 100%
正在等 IO：U_actual(t) = 0%
```

所以，“这张卡平均利用率 50%”，不表示它每个瞬间都只计算了一半。它可以是算一会儿、等一会儿，平均下来有一半时间在计算。

**2. 用一个例子，看带宽公式里的 50% 是怎么来的。**

假设这张卡一直运行同一种请求，每层参数相同：

```text
一层计算时间 C = 4 ms
下一层读取量 V = 8 MiB
只要有数据待读，就能持续获得的带宽 b = 1 MiB/ms
```

当前层计算时，同时读取下一层数据。我们从流水已经运行起来的时候开始观察，当前层的数据已经准备好了。

读完下一层需要：

```text
读取时间 = 读取量 / 带宽
         = 8 / 1
         = 8 ms
```

但是当前层只计算 4 ms。因此运行过程是：

| 时间段 | NPU 在做什么？ | 下一层数据读好了吗？ |
|---|---|---|
| 第 0–4 ms | 计算当前层，同时预取下一层 | 到第 4 ms，只读了 4 MiB，还差 4 MiB |
| 第 4–8 ms | 当前层算完，等待下一层数据 | 继续读取，到第 8 ms 才收齐 |
| 第 8–12 ms | 计算下一层，同时预取再下一层 | 同样的过程再次开始 |

注意：前 4 ms 的读取和计算同时发生，所以每轮是“计算 4 ms + 等待 4 ms”，不是“计算 4 ms + 等待 8 ms”。

```text
每轮经过时间 = 8 ms
其中计算时间 = 4 ms

实际周期平均利用率 = 4 / 8 = 50%
```

现在看带宽公式。要在 4 ms 的计算里藏住 8 MiB 的读取，需要：

```text
B = V / C = 8 / 4 = 2 MiB/ms
```

持续可用的带宽只有 1 MiB/ms，模型估计：

```text
U_est = min(1, b / B)
      = min(1, 1 / 2)
      = 0.5
      = 50%
```

这里 `min(1, x)` 的意思是：x 超过 1 就按 1 算，利用率最高为 100%。

**这个 50%，对应的是上面“一整轮中有一半时间在计算”，不是某一瞬间的计算状态。**

**3. 放在同一张表里，两者的关系就清楚了。**

| 观察方式 | 真实利用率 | 带宽模型的估计 |
|---|---:|---:|
| 看第 2 ms 这一瞬间 | 正在计算，100% | 50% |
| 看第 6 ms 这一瞬间 | 正在等待，0% | 50% |
| 统计第 0–8 ms 这一整轮 | 计算 4 ms / 经过 8 ms = 50% | 50% |

**“现在正在计算”和“平均有一半时间计算”可以同时成立。**

如果只统计第 0–4 ms，真实窗口利用率就是 100%；只统计第 4–8 ms，就是 0%。窗口没有覆盖完整周期时，不必等于模型估计的 50%。

**4. 多张卡时，还要看它们是在一起等，还是错开等。**

现在假设有两张同样的卡，各自持续可获得上例的带宽，每张卡的理想周期平均利用率都是 50%。整机模型估计就是：

```text
U_est = (第 1 张卡的估计 + 第 2 张卡的估计) / 2
      = (50% + 50%) / 2
      = 50%
```

但是，两张卡的真实瞬时状态可能有两种情况：

| 两张卡的时间安排 | 第 0–4 ms | 第 4–8 ms | 完整 8 ms 的整机平均 |
|---|---|---|---:|
| 一起计算、一起等待 | 两张都在算，整机 100% | 两张都在等，整机 0% | 50% |
| 一张计算时另一张等待 | 只有第 1 张在算，整机 50% | 只有第 2 张在算，整机 50% | 50% |

两种情况的带宽模型估计都是 50%，真实瞬时利用率却可以不同。

原因是：**带宽公式知道每张卡平均能忙多少，却没有仅凭这些数字描述“哪张卡恰好在这一刻忙”。**

这个例子人为固定了每张卡的可用带宽。在真实共享 SSD 中，错开还可能改变竞争和获得带宽，进而改变平均利用率；不能用这张教学表证明“错开只影响瞬时值”。

**5. t 和 T，在这里分别是什么？**

```text
t = 一个具体时刻
T = 一段统计窗口的长度
```

在上面一张卡的例子里：

```text
t = 2 ms：这一刻在计算。
t = 6 ms：这一刻在等待。

统计第 0 ms 到第 8 ms：
T = 8 ms。
这个窗口的真实平均利用率是 50%。
```

换到我们实际的实验，取第 2 秒到第 4 秒：

```text
窗口开始 = 2 秒
窗口结束 = 4 秒
T = 4 - 2 = 2 秒

t 可以是 2.1 秒、2.5 秒、3.2 秒……
观察时刻 t 不断向前走，但这个窗口的长度 T 始终是 2 秒。
```

所以，统计 32 张 NPU 的真实窗口利用率，继续使用：

```text
U_window = 所有卡在窗口内的计算时间之和 / (32 * 2 秒)
```

“卡·秒”就是把每张卡的计算时间加起来：一张卡计算 1 秒，计 1 卡·秒；两张卡同时计算 1 秒，计 2 卡·秒。

例如，假设这段时间累计计算了 48 卡·秒：

```text
U_window = 48 / 64 = 75%
```

这和“看这一瞬间有多少张卡在算”不同：窗口公式把整段时间都统计进来了。计算跨过窗口边界时，只计入落在窗口里面的部分。

**6. 为什么真实实验不一定能和带宽模型对上？**

上面的 50% 能对上，是因为假设了请求画像固定、带宽持续可用、计算和下一层读取理想重叠，并且统计覆盖了完整周期。

我们的实验还会遇到请求切换、FIFO 排队、读取集中到达、预取截止时间等情况，因此不能保证模型与任意窗口的实测值一致。

尤其要分清：

- **持续可用的带宽**：只要需要读，就能得到多少速率。上面的模型使用这种含义。
- **瞬间实际读取的带宽**：这个瞬间到底正在读多少。它可能因为数据提前读完而变成 0。

例如，数据已经提前读好，卡正在计算时：

```text
瞬间实际读取带宽 = 0
真实瞬时利用率 = 100%
```

如果把这个 0 直接放进带宽公式，会得到 0%，与计算状态不符。因此，**不能把每个时刻的实际读取带宽直接代入，再求平均，就当作真实窗口利用率。**

**7. 最终保留这三条公式即可。**

```text
第一条：真实的“这一刻”

U_actual(t) = 时刻 t 正在计算的卡数 / N


第二条：按当前条件推算的“理想平均水平”

B_i(t) = V_i(t) / C_i(t)

U_est(t) = sum_i[ min(1, b_i(t) / B_i(t)) ] / N


第三条：实验实际统计的“这一段时间”

U_window = 窗口内所有卡累计的计算时间 / (N * T)
```

其中，`N` 是卡数，`i` 是卡的编号；`V_i(t)`、`C_i(t)` 是这张卡当前请求的每层读取量和每层纯计算时间。计算比值时，读取量、时间和带宽的单位需要一致。`sum_i` 就是逐张卡计算，再把结果加起来。这些公式结果为 0–1，显示百分比时乘以 100%。

读到这里，可以用三个小问题检查理解：

| 问题 | 答案 |
|---|---|
| 模型估计 50%，但当前只有一张卡且正在计算，真实瞬时值是多少？ | 100%。模型的 50% 是理想周期平均，不是当前状态。 |
| 这张卡每轮计算 4 ms、等待 4 ms，统计完整一轮是多少？ | 50%，在这个教学模型里与估计一致。 |
| 我们要报告实验第 2–4 秒的真实平均利用率，用哪个？ | 用 `U_window`，依据日志累计计算时间。 |

本文依据理想单层预取流水模型作算术推导；例子中的数值均为教学假设。关于预取时序与实际实验，可继续阅读同目录的[手稿与实验融合教程](L1_L2_L3_手稿与实验_零基础融合教程.pdf)。
